01 / Mental map

先建立全局地图：多模态模型到底在解决什么

多模态模型不是“把图片和文字一起塞进大模型”这么简单。它真正解决的是接口问题：视觉、文本、音频、深度、页面版式这些不同观测，如何被映射到可比较、可交互、可生成、可检索的计算结构里。

第一层：表示

把输入变成向量、特征图或 token 序列。MLP、CNN、ResNet、ViT、Swin、DINOv2 都在这一层回答“图像如何被编码”。

第二层：对齐

让两个模态的表示进入同一语义坐标系。CLIP、ALIGN、SigLIP 的核心价值在于图文可比较，因此天然适合图搜和开放词表分类。

第三层：交互

让视觉 token 与语言 token 通过 cross-attention、Q-Former、projection 或 early fusion 发生细粒度作用。BLIP、BLIP-2、CoCa、LLaVA、PaliGemma 都在这一层做取舍。

第四层：系统

模型输出必须被 ANN、缓存、重排、监控和业务指标承载。图搜不是一个 encoder，而是一条从数据、向量、索引到线上反馈的系统链路。

为了把知识框架串起来，本文把所有模型放在一个连续谱上：最左侧是只处理向量的 MLP，向右是处理局部空间结构的 CNN 和 ResNet，再向右是把图像切成 patch token 的 ViT 和 Swin；进入跨模态以后，双塔模型把图文映射到同一向量空间，cross-attention 模型保留细粒度关系，桥接器模型复用冻结视觉骨干和 LLM，early fusion 模型试图把不同模态变成同一种序列。

先分清四种接口

第一种接口是分类：模型输出一个类别或概率分布。ResNet、ViT、DeiT、ConvNeXt 这类视觉骨干最早在这个接口下被训练和评估。第二种接口是检索：模型输出可比较向量，系统通过相似度寻找近邻。CLIP、ALIGN、SigLIP、ImageBind 和 VLM2Vec 都主要服务这个接口。第三种接口是生成：模型输出自然语言或混合模态内容。BLIP、CoCa、PaLI、PaliGemma、LLaVA、Chameleon 更接近这个接口。第四种接口是执行：模型必须根据视觉状态使用工具、操作 GUI、调用检索或执行动作，这时纯粹的 encoder 已经不够，需要语言模型、策略层和反馈闭环。

本文的核心判断

多模态架构的学习顺序应当是“先接口，后模型”。图搜需要的是稳定 embedding、ANN 索引和负例闭环；视觉问答需要视觉 token 与语言 token 的交互；文档检索可能需要 multi-vector late interaction；视觉 Agent 需要动态分辨率、定位、工具调用和可靠降级。把这些场景都归入“多模态大模型”会遮蔽真正的工程约束。

02 / MLP

从 0 到 1：MLP 是所有架构的基本语法

如果把深度模型拆到最小，最常见的部件仍然是 MLP：线性变换、非线性激活、再线性变换。Transformer 的 FFN、ViT 的 MLP block、CLIP 的 projection、LLaVA 的视觉语言 connector、BLIP-2 的 Q-Former 输出映射，本质上都在使用 MLP 这一类可学习函数。

MLP 做了三件事

第一，它把输入向量投到新的坐标系。一个线性层可以旋转、缩放、组合特征；非线性激活让多层叠加不再退化为单个线性变换。第二，它通过反向传播学习参数。Rumelhart、Hinton 与 Williams 在 1986 年的工作说明，网络可以根据输出误差反向调整连接权重 [S01]。第三，它提供表达能力。Hornik、Stinchcombe 与 White 证明，标准多层前馈网络在一定条件下具有通用逼近能力 [S02]。

但这里有一个容易被忽略的分界：能表示某个函数，不等于能以合理数据量、合理计算量、合理泛化误差学到这个函数。这也是为什么视觉模型不会停留在朴素 MLP。图像有局部性、平移等变性、多尺度结构、纹理和形状层次。CNN 把局部卷积作为归纳偏置，ResNet 用残差解决深层优化，ViT 把图像切成 patch token 交给自注意力，Swin 再把窗口和层级结构带回高分辨率视觉任务。MLP 是语法，不是整套语言。

作为基本层

Transformer block 里的 FFN 是逐 token 的 MLP。它不负责 token 间通信，而负责对每个 token 的通道维特征做非线性变换。

作为投影头

CLIP/SigLIP 把视觉和文本 encoder 的输出投到同一 embedding 维度。这个 projection 往往决定相似度空间的可训练形态。

作为连接器

LLaVA 系列的视觉到语言连接器可以是线性层或 MLP。它把视觉 token 转成 LLM 能消费的 token 表示 [S26]。

作为完整视觉骨干

MLP-Mixer 证明，重复的 token-mixing 与 channel-mixing 也能构成视觉模型，但它对数据规模和正则更敏感 [S07]。

MLP-Mixer 的价值不是“替代 ViT”，而是拆解视觉建模

MLP-Mixer 的设计很干净：一类 MLP 沿着空间 token 维度混合信息，另一类 MLP 沿着通道维度混合信息 [S07]。它没有卷积，也没有注意力。因此它提供了一个重要思想实验：视觉模型至少要解决两种混合，一种是位置之间的信息交换，另一种是通道之间的特征组合。CNN 用卷积核做局部空间混合，用后续层做通道组合；ViT 用注意力做全局 token 交互，用 FFN 做通道变换；Mixer 则用两个方向的 MLP 完成这两件事。

这解释了为什么“MLP、CNN、Transformer”不是互斥宗教。一个现代多模态系统里，视觉骨干可能是 ViT，图文 projection 是 MLP，LLM 内部每层有 FFN，adapter 是 MLP，reranker 又可能用 cross-attention。架构不是标签，而是数据流中每一段的函数选择。

常见误区

不要把 MLP 的通用逼近能力解释成“只要足够大就可以不用结构”。在视觉和多模态场景中，结构是样本效率、计算模式、延迟、可解释性和错误形态的共同约束。一个没有合适归纳偏置的模型可能最终能拟合训练集，却很难在长尾图像、商品变体、文档版式和多语言查询上稳定泛化。

03 / Vision backbone

视觉骨干：CNN、ResNet、ViT、MLP-Mixer 与 Swin

多模态模型的视觉能力先取决于视觉骨干。语言模型再强，如果视觉 encoder 把图像压坏、丢掉小字、忽略局部关系或无法处理高分辨率，后面的图文对齐和问答都会在错误输入上工作。

CNN 与 ResNet：局部结构和深层优化

CNN 的核心偏置是局部感受野和权重共享。图像中相邻像素更相关，同一个边缘或纹理可以在不同位置出现；卷积把这种假设写入结构，因此在有限数据下具有强样本效率。ResNet 的贡献是把深层网络从“直接学习目标映射”改成“学习相对于输入的残差函数”，缓解深层网络退化和优化困难 [S04]。这一点在多模态里仍然重要：很多视觉 encoder、检测器、OCR 和特征提取 pipeline 都继承了 CNN 时代的层级视觉直觉。

ResNet 之后的视觉模型并不是抛弃 CNN，而是在重新分配归纳偏置。ViT 更依赖数据和预训练，Swin 把局部窗口和层级结构带回 Transformer，ConvNeXt 则反向证明现代化 ConvNet 仍能与 Transformer 竞争 [S40]。工程上应当问的是：任务是否需要高分辨率、定位、密集预测、低延迟、小样本泛化，还是只需要一个全局图像 embedding。

ViT：图像被切成词以后发生了什么

ViT 的关键动作很简单：把图像切成固定大小 patch，把每个 patch 投影成 token，再把 token 序列交给标准 Transformer [S05]。这一步把视觉问题改写为序列建模问题。它的优势是全局交互和结构统一，尤其适合与文本 encoder、LLM 和统一 token 模型连接。CLIP、SigLIP、BLIP-2、PaliGemma 等主流图文模型大量使用 ViT 或 ViT 变体作为视觉 encoder [S16,S18,S21,S24]。

ViT 的代价也很清楚。第一，patch token 会压缩局部细节，patch 太大时小字、细粒度纹理和小物体容易被淹没；patch 太小时 token 数上升，注意力成本增加。第二，原生 ViT 缺少 CNN 的局部平移偏置，在小数据上需要更强训练 recipe。DeiT 用蒸馏 token 和 teacher-student 策略说明，训练方法可以显著改变 ViT 的数据效率 [S06]。第三，密集预测和高分辨率输入需要层级结构、窗口注意力、动态分辨率或特定 decoder。

Swin：把层级和窗口带回 Transformer

Swin Transformer 的问题意识来自视觉和语言的差异：图像实体尺度变化大，像素分辨率远高于文本序列。Swin 用 shifted window 限制注意力范围，同时通过窗口偏移连接跨窗口信息；再通过 patch merging 构建层级特征 [S08]。这使它更适合检测、分割和高分辨率密集预测。对多模态系统来说，Swin 的意义不是替代 CLIP-ViT，而是提醒我们：当任务需要定位和局部结构时，全局单向量 embedding 往往不够。

自监督视觉预训练：BEiT、MAE、DINO 与 DINOv2

视觉骨干不只靠分类标签训练。BEiT 把 BERT 式 masked modeling 移植到视觉领域，要求模型根据可见 patch 恢复离散视觉 token [S09]。MAE 使用高遮盖率和非对称 encoder-decoder，让 encoder 只处理可见 patch，decoder 负责重建缺失像素，因而降低预训练计算并保持可扩展性 [S10]。DINO 走自蒸馏路线，显示自监督 ViT 特征可以呈现语义分割线索，并在 kNN 分类中表现强 [S11]。DINOv2 进一步强调 curated 数据、规模化训练和蒸馏，目标是得到无需微调也能泛化的通用视觉特征 [S12]。

骨干/预训练 核心机制 适合接口 主要风险
ResNet / CNN 局部卷积、层级特征、残差优化 分类、检测、分割、传统视觉特征 开放词表和跨模态语义接口弱
ViT patch token、全局自注意力 图文 encoder、VLM 视觉输入、分类 token 数、分辨率、小物体和小数据依赖
MLP-Mixer token-mixing 与 channel-mixing 视觉骨干对照、轻量实验 动态关系建模弱，训练依赖 recipe
Swin 窗口注意力、shifted window、层级结构 检测、分割、高分辨率视觉任务 图文共享空间仍需额外对齐目标
DINOv2 / MAE / BEiT 自蒸馏、遮盖重建、视觉 token 预测 通用视觉特征、初始化、无标签预训练 未必天然支持语言查询

在图搜场景中，视觉骨干最容易被误判。单纯视觉特征可以处理相似款、材质、颜色和构图，但难以理解“适合通勤的深蓝色托特包”这类语言查询。图文对齐模型可以处理自然语言，但可能丢失细粒度 SKU 差异。一个成熟系统通常不会只选一个骨干，而会组合全局 embedding、局部特征、类目/属性模型、OCR、检测器和 reranker。

04 / Objectives

预训练目标：监督、遮盖、蒸馏、对比与生成

架构决定信息如何流动，训练目标决定模型被迫学什么。多模态模型的很多差异，不在 encoder 名字，而在目标函数如何定义“相似”“缺失”“正确”“可描述”和“可回答”。

监督分类：学类别，不等于学语义空间

ImageNet 式监督分类把图像映射到固定标签集合。它能训练强视觉特征，却把世界压进预定义类别。CLIP 论文的问题意识正来自这里：传统视觉系统需要固定类别，新的视觉概念需要额外标注数据 [S16]。如果业务只需要封闭类目识别，监督分类仍然有效；如果业务要求开放查询、跨语言表达、图文互搜，就需要对齐目标。

遮盖与重建：学上下文，不直接学查询

BEiT 和 MAE 说明，模型可以通过恢复被遮盖内容学习视觉结构 [S09,S10]。这类目标的优点是无需人工标签，能利用大量原始图像；缺点是重建像素或视觉 token 不等价于理解用户意图。一个能补全图像 patch 的模型，不一定知道“这张商品图是否符合用户用自然语言描述的风格”。因此自监督视觉特征常作为视觉骨干或初始化，而不是完整图搜系统。

蒸馏：把强模型的行为压到可部署模型

DeiT 用蒸馏 token 提高 ViT 在 ImageNet 训练下的效率 [S06]。DINO/DINOv2 用 teacher-student 自蒸馏学习无标签视觉表征 [S11,S12]。在多模态工业系统里，蒸馏还常用于把 cross-encoder、生成式 VLM 或大尺寸 embedding 模型的判断迁移到小模型，换取延迟和成本。蒸馏不只是压缩，它也是把某种判断标准显式传给另一个接口。

对比学习：把相似性变成几何结构

CLIP、ALIGN、SigLIP 的核心都是图文配对监督。给定图像和文本，模型要把真实配对拉近，把错误配对推远 [S16-S18]。这种目标特别适合检索，因为它直接训练相似度空间。CLIP 使用 batch 内 N x N 配对和对称 cross entropy；ALIGN 使用更大规模的噪声 alt-text 数据；SigLIP 把 softmax 归一化换成 pairwise sigmoid loss，减少对全局 batch 相似度矩阵的依赖 [S16-S18]。

生成目标：让模型学会说，但也带来幻觉风险

BLIP、CoCa、PaLI、PaliGemma、LLaVA 等模型加入语言生成目标，让模型能够 caption、回答问题、执行指令或生成结构化文本 [S20-S26]。这让多模态模型从“可比较”进入“可交互”。但生成目标也会引入语言模型的先验：当视觉证据弱、训练数据有偏或 prompt 暗示强时，模型可能用语言常识补全不存在的图像细节。图文对齐强不等于视觉事实可靠，能生成流畅答案也不等于能稳定定位和计数。

目标 模型代表 模型被迫学习的能力 对工程接口的影响
监督分类 ResNet、ViT、DeiT 固定标签边界和类内不变性 适合封闭分类，不适合开放语言查询
遮盖重建 BEiT、MAE、4M 上下文、结构、被遮盖内容预测 适合预训练和 any-to-any 任务，但需下游对齐

05 / Alignment

图文对齐：CLIP、ALIGN、SigLIP 为什么支撑图搜

图搜的本质是把“图片”和“查询”放到同一个可比较空间。CLIP、ALIGN、SigLIP 的共同贡献，是把图文匹配从任务模型变成可复用的 embedding 接口。

CLIP：分类器被改造成语言查询

CLIP 训练一个图像 encoder 和一个文本 encoder，用自然语言监督学习共享 embedding 空间 [S16]。训练时，真实图文对被拉近，batch 内其他图文组合被推远。推理时，分类标签可以写成自然语言 prompt，图片和文本类别名称进入同一向量空间，通过相似度完成零样本分类。OpenAI 官方博客也把这一能力解释为用自然语言概念引用视觉类别 [S35]。

这一步对图搜的意义极大。传统图像检索依赖颜色、纹理、局部特征或监督类目；CLIP 式模型允许用户用自然语言描述目标，并在同一空间中检索图像。它还允许“以图搜图”和“以文搜图”共享同一索引。缺点是，CLIP 的全局向量会把复杂图像压成一个点，细粒度关系、局部位置、数量、文本小字、属性组合和否定表达都可能出错。

ALIGN：噪声数据可以被规模稀释，但不能被规模洗白

ALIGN 用超过十亿图像 alt-text 对训练简单双塔模型，强调在大规模 noisy data 上学习图文表示 [S17]。它证明了一个工业现实：图文数据越大，人工清洗越难；如果训练目标和模型容量合适，规模可以抵消部分噪声。但噪声不会消失，它会转化为偏差、长尾错误、跨语言不均衡和安全问题。对于电商图搜，商品标题、类目、属性、用户行为、详情页和图片质量都在决定 embedding 的语义边界。

SigLIP：把全局 softmax 的 batch 依赖拆开

SigLIP 的关键变化是把标准对比学习中的 softmax 换成 pairwise sigmoid loss。论文指出，sigmoid loss 只作用在图文对上，不需要为了归一化而看到全局 pairwise similarity 矩阵，因此在 batch size 和训练效率上提供了不同取舍 [S18]。这对工程训练很重要：很多团队并没有超大 batch 的基础设施，loss 对 batch 全局视图的依赖越强，复现和扩展越困难。

SigLIP2 则体现了图文 encoder 的下一步方向：在原始 SigLIP 基础上加入 captioning-based pretraining、自监督 loss、online data curation、多语言数据和 native aspect ratio 等 recipe，以提升语义理解、定位和 dense feature [S19]。这说明图文 encoder 不再只是“全局相似度模型”，而是在向多语言、局部特征和 VLM 视觉底座扩展。

早期 VLP 为什么没有消失

在 CLIP 之前，ViLBERT、LXMERT、UNITER 这类模型更多依赖 region features 与跨模态 attention。ViLBERT 用视觉和语言双流，通过 co-attentional transformer layers 交互 [S13]；LXMERT 将模型拆成 object relationship encoder、language encoder 和 cross-modality encoder [S14]；UNITER 学习联合图文表示，使用 masked language modeling、masked region modeling、image-text matching 和 word-region alignment [S15]。这些模型不如双塔适合大规模离线召回，但它们提醒我们：细粒度关系需要 token/region 级交互。今天的 reranker、文档理解、VQA 和 grounding 仍在用这个思想。

图搜中的基本取舍

如果第一目标是亿级图库召回，优先双塔 embedding，因为商品向量可以离线预编码并进入 ANN 索引。如果第一目标是理解局部关系，例如“左边有红色袖口的白衬衫”，只靠全局向量通常不稳，需要局部 token、检测器、属性模型或 reranker。如果第一目标是用语言解释为什么命中，生成式 VLM 可以补充，但不能替代召回模型。

06 / VLM

视觉语言模型：BLIP、BLIP-2、CoCa、PaLI、PaliGemma 与 LLaVA

双塔模型解决“可比较”，视觉语言模型解决“可交互”。从 BLIP 到 BLIP-2，再到 PaliGemma 和 LLaVA，核心问题都是同一个：视觉 token 如何进入语言模型，并保留足够证据让语言输出可信。

BLIP：理解与生成被放回同一框架

BLIP 针对早期 VLP 的一个矛盾：很多模型擅长理解任务或生成任务，但不同时擅长两者。BLIP 提出 Multimodal mixture of Encoder-Decoder，并用 captioner 与 filter 对 noisy web captions 做 bootstrapping [S20]。这使它能在图文检索、caption、VQA 等任务之间迁移。架构上，BLIP 说明多模态模型不必在“embedding 模型”和“caption 模型”之间硬切分；同一训练框架可以同时服务表示和生成。

BLIP-2：冻结骨干之后，桥接器变成关键

BLIP-2 的现实主义在于降低端到端训练成本。它冻结预训练图像 encoder，冻结大型语言模型，中间用 lightweight Querying Transformer，也就是 Q-Former，桥接视觉和语言 [S21]。两阶段训练先从冻结图像 encoder 学视觉语言表示，再从冻结 LLM 学视觉到语言生成。这条路线后来成为很多 VLM 的基本工程形态：视觉 encoder 提供 token，桥接器压缩和转换 token，LLM 负责语言推理和输出。

桥接器的代价是信息瓶颈。Q-Former、projection、resampler 或 MLP connector 会决定视觉细节如何进入 LLM。压缩太强会丢失小字、坐标、局部关系；压缩太弱会让 token 数和推理成本失控。很多 VLM 的真实差异，并不只在 LLM 参数量，而在视觉 token 的分辨率、数量、位置编码、连接器容量、训练阶段和数据配比。

CoCa：对比与 caption 的合流

CoCa 把 contrastive loss 和 captioning loss 放进一个 encoder-decoder 模型。它在 decoder 前半段保留 unimodal text representation，后半段通过 cross-attention 接入图像 encoder；同时对 unimodal 图文 embedding 做对比学习，对 multimodal decoder 输出做 captioning [S22]。这提供了一个优雅范式：同一计算图可以同时训练检索友好的向量和生成友好的语言输出。

PaLI 与 PaliGemma：多语言、开放组件与 transfer

PaLI 将视觉和语言组件共同扩展，使用多语言图文任务训练生成式 VLM [S23]。PaliGemma 则是更开源、可迁移的轻量路线：论文描述其基于 SigLIP-So400m 视觉 encoder 与 Gemma-2B 语言模型 [S24]；Google Developers 博客也公开解释了 PaliGemma 由 SigLIP 视觉模型与 Gemma 语言模型组合而成 [S25]。对工程团队来说，PaliGemma 的价值不只是模型性能，而是它把“强视觉 encoder + 可用语言模型 + 可微调接口”包装成可迁移的开放基线。

LLaVA：小连接器也能建立强 baseline

LLaVA 用视觉 encoder、投影层和 LLM 构建多模态助手，并通过语言模型生成的视觉指令数据做 tuning [S26]。它的启发是：不一定要从头训练大规模多模态模型，冻结或复用已有视觉 encoder 和 LLM，再训练连接器和指令数据，也能得到强 baseline。它的边界同样明确：如果视觉 encoder 没有捕获细节，或者指令数据没有覆盖特定任务，LLM 的语言能力可能会掩盖视觉证据不足。

07 / Unified multimodality

统一多模态：ImageBind、4M、Chameleon 与 early fusion

图文不是多模态的终点。真实世界还有音频、视频、深度、热成像、IMU、文档版式、网页、GUI 和动作。统一多模态的关键问题是：不同模态是否必须两两配对，是否能共享 token 空间，是否能用同一模型完成输入和输出。

ImageBind：图像作为跨模态枢纽

ImageBind 学习图像、文本、音频、深度、热成像和 IMU 六种模态的共享 embedding。它的重要判断是：不必收集所有模态两两配对的数据，只要每种模态与图像配对，就可以通过图像枢纽绑定到同一空间 [S27]。这对工程很有启发。现实中 audio-text、depth-text、IMU-text 数据很难大规模配齐，但 image-paired 数据更常见。图像在这里不是唯一真理，而是最方便的公共锚点。

4M：把输入输出都 token 化

4M 将文本、图像、几何、语义模态和神经网络 feature maps 映射到离散 token，并用统一 Transformer encoder-decoder 做 multimodal masked modeling [S28]。它的目标不是只做图文检索，而是让模型从任意模态子集预测任意目标模态。这个方向很强，但系统复杂度也高：每个模态的 tokenizer、mask 策略、目标权重、输出空间和评测方式都会影响最终模型。

Chameleon：mixed-modal early fusion 的野心

Chameleon 把图像和文本都作为 token，在同一个自回归序列里处理，支持任意交错的图文理解和生成 [S29]。这条路线的优势是接口统一：模型看到的是混合文档，而不是先视觉后语言的管线。它的难点也直接来自统一：图像 token 的数量、压缩和生成质量，文本能力保留，训练稳定性，对齐和安全，都比桥接器路线更难。

统一不是免费的

统一多模态常被描述为最终方向，但工程上必须付费。双塔模型可离线编码，成本清晰；cross-attention 精度更强，但实时成本高；桥接器路线复用现有 LLM，但视觉信息会被压缩；early fusion 语义上最统一，但训练、推理和安全成本最大。统一接口的收益，要和业务是否真的需要统一输出一起衡量。

只需要召回

优先 CLIP/SigLIP/VLM2Vec 式 embedding。统一生成式模型的语言能力不一定带来召回收益，反而可能增加成本。

需要解释和问答

需要 BLIP-2、PaliGemma、LLaVA 或同类 VLM。此时评测必须包含幻觉、定位、小字和拒答边界。

需要页面/文档理解

考虑视觉文档 embedding、OCR、layout model 和 late interaction。单纯文本抽取会丢掉版式和图表线索。

需要跨传感器绑定

ImageBind 式图像枢纽提供思路，但生产系统要审查每个模态的数据质量、采样频率和误差成本。

08 / Search system

图搜系统：embedding、late interaction、ANN 与 rerank

图搜不是“调用一个 CLIP 模型”。模型只是把图片和文本变成可比较对象；真正的线上系统还需要数据治理、特征生成、向量索引、召回、重排、过滤、监控和反馈闭环。

单向量召回：最快，也最容易丢细节

CLIP、ALIGN、SigLIP 这类双塔模型适合单向量召回，因为商品向量可离线生成，用户文本或图片 query 在线编码后与索引中向量比较。Faiss 论文说明，大规模相似度搜索要处理 GPU k-selection、PQ、IVF 等工程问题 [S33]；HNSW 则通过多层 navigable small world graph 做近似最近邻搜索 [S34]。这意味着模型维度、向量归一化、索引类型、压缩率和召回率是联动变量。

单向量的弱点是它只能给每个图片一个全局点。商品图里可能同时有主体、背景、文字、配件、材质、品牌标识和模特姿势；全局 embedding 会把这些因素混合。对于“找同款”或“相似风格”足够时，单向量很强；对于“不要条纹”“左下角有标签”“白底图里小瓶身红字”这样的查询，单向量需要局部特征、OCR、属性模型或 reranker 支撑。

Late interaction：介于双塔和 cross-encoder 之间

ColBERT 提出 late interaction：query 和 document 独立编码，但不是压成一个向量，而是保留 token-level 表示，之后用便宜的 MaxSim 交互计算细粒度相似度 [S30]。它比 cross-encoder 更容易离线预编码，比单向量更能保留细节。ColPali 把这个思想迁移到视觉文档检索，直接从页面图像生成 multi-vector embeddings，并使用 late interaction 匹配查询和页面 [S31]。这对 PDF、表格、截图、票据和商品详情页很关键，因为版式本身就是信息。

VLM2Vec：把 VLM 转回 embedding 模型

VLM2Vec 的问题意识是，通用文本 embedding 有 MTEB 这类生态，但通用多模态 embedding 进展较慢。论文提出 MMEB，覆盖分类、VQA、多模态检索和 visual grounding，并用对比训练把 VLM 转成 instruction-aware fixed-dimensional embedding 模型 [S32]。这说明生成式 VLM 和 embedding 模型正在合流：VLM 的视觉语言理解能力可以被蒸馏或再训练到检索接口，但最终仍要面对向量维度、索引成本和业务指标。

09 / Decision framework

选型框架：面对业务场景如何判断架构路线

多模态选型不是模型榜单问题，而是接口、数据、延迟、错误成本和迭代闭环问题。一个高分 VLM 不一定适合做第一阶段召回，一个强 embedding 模型也不一定能回答视觉问答。

第一问：你要的输出是什么

如果输出是一个类别，优先考虑监督视觉骨干或轻量 ViT。若输出是候选集合，优先 embedding + ANN；若输出是候选排序，加入 late interaction 或 cross-encoder rerank；若输出是文本解释或结构化字段，使用 VLM；若输出是动作，则还需要工具层、状态机和安全边界。把所有输出都交给同一个 VLM，是最常见的过度设计。

第二问：输入的难点在哪里

自然图像以主体和背景为主，CLIP/SigLIP 全局 embedding 往往已经有强 baseline。商品图像难在 SKU 细节、材质、风格、类目和用户行为信号，需要领域 SFT、硬负例和属性建模。文档图像难在小字、表格、版式和跨页引用，可能需要 OCR、layout-aware pipeline 或 ColPali 式视觉页面 embedding。视频和 GUI 难在时间、状态变化和动作反馈，需要动态分辨率、时间编码和工具调用。

第三问：错误成本是什么

推荐场景的错误可以通过用户反馈和排序兜底吸收；医疗、金融、合同、合规和工业质检场景不能把“看起来合理的语言输出”当事实。生成式模型的错误更像陈述错误，embedding 的错误更像排序错误，检测器的错误更像定位错误。不同错误类型对应不同监控指标。

第四问：数据闭环是否存在

没有数据闭环时，模型选型很容易停在 paper benchmark。图搜需要正负样本、点击/收藏/购买/跳出信号、人工难例、类目纠错和 query 改写日志。VLM 需要任务指令、标准答案、拒答样本、对抗样本和事实校验器。ANN 系统需要索引重建监控、embedding 漂移监控、召回候选分布和延迟分位数。没有这些，模型越复杂，误差越难定位。

上线前最低门槛

图搜模型至少要分别通过离线检索评测、长尾 query 评测、类目穿透评测、索引压缩评测、线上灰度和人工 badcase review。VLM 至少要通过事实一致性、拒答、定位、小字、表格、幻觉和延迟评测。只看公开 benchmark 或 demo 图片，不能作为上线依据。

10 / Pitfalls and reading

常见误区、前沿问题与必读资料

误区一：把 embedding 好当成理解好

embedding 好意味着相似度空间对某些任务有用，不代表模型能可靠解释、定位、计数或推理。CLIP/SigLIP 是图搜和零样本分类的强接口，但如果任务要求回答“为什么这两张图不同”，还需要局部证据、属性模型或 VLM。

误区二：把 VLM 当成召回系统

VLM 能看图说话，不代表它适合全库检索。召回系统要求离线预编码、低延迟、稳定相似度和可控索引成本。VLM 更适合理解候选、生成解释、抽取字段或做重排。把生成模型放在第一阶段召回，会把成本和延迟推到最难承受的位置。

误区三：只看模型，不看数据口径

ALIGN 的 noisy alt-text、BLIP 的 caption bootstrapping、SigLIP2 的 online data curation、DINOv2 的 curated data pipeline 都说明：数据口径不是背景，它就是模型能力的一部分 [S12,S17,S19,S20]。在电商、医疗、工业、文档、短视频等垂直场景，数据分布比模型名更早决定上限。

误区四：把多语言当作翻译问题

多语言图搜不是把 query 翻成英文再搜。商品标题、文化偏好、颜色词、类目词、品牌别名和单位表达都会改变检索意图。SigLIP2 和 PaLI/PaliGemma 的多语言路线说明，多语言能力需要进入训练数据和模型接口 [S19,S23,S24]。

接下来最值得关注的前沿问题

  • 视觉 token 的经济学：分辨率、patch size、token 压缩、动态分辨率和窗口注意力如何共同决定 VLM 成本。
  • VLM-to-embedding：VLM2Vec 这类路线能否把复杂视觉语言理解稳定转成可索引向量。
  • 多向量检索系统：ColPali 说明视觉文档场景可能从 OCR-first 转向 image-first，但索引成本和服务形态需要进一步工程化。
  • 统一 token 模型：4M 和 Chameleon 指向 any-to-any 与 mixed-modal early fusion，但训练稳定性、可控生成和安全边界仍是核心难题。
  • 评测到线上指标的裂缝：公开 benchmark 很难覆盖业务类目、长尾 query、禁限内容、实时库存、地域语言和反馈偏差。
