01 / Executive View

结论摘要：三类模型面，三类后训练

多模态 embedding/rerank 后训练的关键，不是选择一个听起来先进的算法，而是先确认模型在哪里做决策。纯向量模型、cross-encoder reranker、生成式 reranker 或检索代理的可优化信号不同，SFT、RL、OPD 的价值也随之改变。

高Embedding

成熟路线是 instruction-conditioned contrastive tuning、hard-negative curriculum、teacher/reranker distillation、synthetic data 与 MRL。VLM2Vec、VLM2Vec-V2、Qwen3/Qwen3-VL 系列均支持这一判断 [S01][S02][S03][S04]。

高Rerank

reranker 有明确候选集、排序标签和下游指标，SFT 与 RL 都更自然。MM-R5 用 SFT 构造 reasoning chain，再用 reranking reward 和 reasoning reward 优化；Pailitao-VL 把工业重排推向 listwise compare-and-calibrate [S06][S08]。

中OPD

OPD 的核心是 student 在自己的状态分布上产生 token 轨迹，teacher 给密集反馈。它适合多模态 reasoning、生成式 rerank、SFT 到 RLVR 的预对齐；对纯 dense embedding 则通常只能作为间接数据和教师信号来源 [S13][S14][S15][S16]。

一句话判断：embedding 后训练不要直接追逐 RL/OPD 名称；先把对比学习、指令化、难负例、蒸馏和评测数据闭环做到位。rerank 或检索代理如果能稳定定义 reward，才进入 SFT plus RL。OPD 放在会生成推理、解释、比较或检索动作的模型面，而不是直接替代向量损失。

方案 对 dense embedding 对 rerank 上线前必须证明
SFT-like 指令调优 高可行，但通常表现为带指令的对比训练或蒸馏，不是传统 token likelihood SFT。 高可行，可训练输入格式、跨模态证据链、yes/no 或 listwise 打分。 跨域 Recall@K、NDCG、难负例鲁棒性、指令迁移收益。
RL 直接做向量训练可行性偏低，常遇到离散 top-k、索引刷新、credit assignment 与高方差问题。 中到高，适合候选集固定、reward 稳定、排序或 answerability 可度量的场景。 reward 与真实业务指标相关，未发生 judge hacking，延迟预算未被打穿。
OPD 直接可行性低到中，因为纯向量编码器没有 token 轨迹；可间接生成更好的 queries、rationales、教师分数。 中到高，尤其是生成式 reranker、视觉推理 reranker、SFT 到 RLVR 的过渡阶段。 student-state distribution drift 下降，OPD 之后 RL 或 rerank 指标真实提升。
02 / Model Surfaces

问题边界：embedding、rerank 与生成式决策

多模态检索系统通常被拆成召回、粗排、精排、重排和答案生成。embedding 负责把 query、图像、视频、文档页、商品或文本映射到共享空间；reranker 在较小候选集上做更贵的跨注意力或 listwise 比较。二者的训练目标相邻，但不是同一个问题。

图 1：同一个检索系统中，embedding、rerank、policy 的后训练信号不同。OPD 和 RL 的自然位置通常在右侧的生成式或可行动决策面。

四个概念必须分开

模型面 输出 主要训练信号 后训练问题
Dense embedding 单向量或少量向量 对比损失、triplet、in-batch negatives、teacher score distillation 让相似项更近、混淆项更远，同时保持跨模态泛化。
Late interaction 多向量集合与 max-sim 聚合 页面 patch/token 级监督、late-interaction ranking loss 保留文档图像细节，换取更高存储和检索计算。
Cross-encoder reranker 候选得分或 yes/no logits pairwise/listwise SFT、teacher ranking、calibrated labels 让模型在候选集合内做精细比较，而不是负责全库召回。
Generative reranker / retrieval agent 排序、解释、动作、证据链 SFT traces、OPD、RLVR、task reward 对齐推理过程、减少分布漂移，并让 reward 绑定业务目标。

因此，“SFT 是否能训练 embedding”需要拆开回答。如果 SFT 指经典语言模型 token likelihood，它并不是 dense embedding 的主损失；如果 SFT 指面向任务指令、query-document pair、hard negative、teacher score 的监督微调，则它是当前最可落地的后训练范式之一。Qwen3 Embedding/Reranker 与 Qwen3-VL-Embedding/Reranker 的公开资料显示，工业级 embedding 往往使用多阶段训练：无监督或大规模弱监督预训练，随后是任务数据、指令、难负例和 reranker/distillation 信号 [S03][S04]。

03 / Evidence Map

证据图谱：学术路线与工业路线

2024 到 2026 年的公开资料给出两个互补方向：学术界把多模态 embedding 从图文检索扩展到文档页、视频、视觉问答和 grounding；工业界把它接入商品检索、推荐、企业 RAG 与统一多模态 API。

04 / SFT

SFT：向量模型的可行路径与误用边界

对多模态 embedding 而言，SFT 最容易被误解。传统语言模型 SFT 通过 teacher-forced token loss 学会输出文本；dense embedding 则输出向量，主要目标是距离结构。因此，严格说，embedding 的“后训练”常常不是 token SFT，而是 supervised representation tuning：在带指令、带正负样本、带教师分数的数据上优化对比或排序蒸馏损失。

可行路径一：指令化对比训练

VLM2Vec 的关键信号是把任务说明纳入 embedding 输入，使同一个 VLM 可以在不同任务下形成可比较表示 [S01]。这对工业系统尤其重要：商品图搜、图文 RAG、视觉文档问答、视频检索的相似性定义不同。如果不把任务写入输入，模型会把“相似图片”“同款商品”“能回答问题的文档页”“同一事件视频片段”混成一种距离。

落地时，训练样本至少应包含四元组：(instruction, query, positive, negatives)。instruction 不是装饰性前缀，而是决定监督语义的条件。负例也不能只靠随机采样，需要包括同类商品、近似布局文档页、相同 OCR 但不同图像证据、相似视频封面但事件不同的 confusers。

可行路径二：难负例与 reranker 蒸馏

Qwen3 和 Qwen3-VL 的公开资料都把 embedding 与 reranker 放在同一系统里理解。embedding 负责高覆盖召回，reranker 负责高精度比较；reranker 的分数、排序和失败样本反过来构成 embedding 后训练数据 [S03][S04]。

这个闭环比简单扩充正样本更重要。对于多模态检索，最常见失败不是“模型完全不懂图片”，而是相似外观、同品牌不同型号、同页面不同表格、视频同封面不同片段、商品标题属性缺失等细粒度错误。hard-negative curriculum 能把这些错误显式喂给向量模型。

可行路径三：MRL 与多粒度服务

Qwen3 系列公开提到 Matryoshka Representation Learning，这代表一种工程化诉求：同一模型输出可以在不同向量维度上服务不同成本层级 [S03][S04]。后训练时不能只看最高维度指标，也要验证缩短维度后的 Recall@K、类目长尾、跨语言、跨模态和 latency cost。

SFT 数据 训练目标 可接受证据 常见陷阱
人工或业务日志 pair/triplet 对比损失、margin loss、multi-negative loss 冷启动类目和跨模态 holdout 提升，而非只在训练相邻类目提升。 随机负例过易，导致线上 top-k 几乎无改善。

05 / RL

RL：更适合 rerank 与检索代理

RL 的优势是直接优化目标函数以外的任务收益；它的代价是高方差、reward 设计、线上分布模拟和训练成本。对 dense embedding 来说，top-k 检索结果依赖索引、近邻搜索和离散候选集合，直接 credit assignment 很难。对 reranker 来说，候选集固定、排序指标明确，RL 的落点自然得多。

为什么 dense embedding 不应优先做直接 RL

纯向量模型的输出是连续向量，但业务 reward 往往来自离散 top-k：用户是否点击、答案是否能被生成、候选是否同款、排序是否正确。训练时还要面对索引刷新、ANN 近似误差、负例池漂移、batch 内样本不代表线上候选集等问题。把这些都塞进 RL，通常会让训练变得复杂而不稳定。

这并不表示 RL 与 embedding 无关。更合理的路径是：先用 reranker、检索代理或 query reformulator 做 RL，得到更高质量的排序、查询改写、hard negatives 或 teacher scores，再蒸馏回 embedding。这样 RL 优化发生在能定义动作和 reward 的模型面，embedding 仍用稳定的表征损失吸收结果。

reranker 的 RL 可行性更高

MM-R5 是一个明确例子：它先用 SFT 让模型生成多模态检索 reasoning chain，再用任务特定 reranking reward 和 reasoning template reward 继续优化 [S06]。这说明 RL 在 rerank 面有三个优势：候选集较小，reward 可以绑定 NDCG/MRR/answerability，生成式 reasoning 能被格式或证据奖励约束。

Pailitao-VL 的工业信号也指向同一方向：大规模商品视觉检索的后段重排从 pointwise 走向 listwise compare-and-calibrate policy [S08]。对商品搜索而言，用户看到的是一页结果，而不是孤立的 query-item pair；listwise 信号能显式学习同屏候选之间的替代、互补和校准关系。

RL 对象 动作空间 reward 来源 推荐程度
Dense encoder 向量位置或相似度结构 top-k 命中、点击、问答成功 低仅建议研究性探索或非常成熟的模拟器场景。
Cross-encoder reranker 候选得分、pairwise/listwise order NDCG、MRR、人工偏好、教师排序 高候选集稳定时可以做 SFT plus RL。
Generative reranker 解释、证据链、最终排序 排序指标、证据引用、格式约束、答案可用性 高适合视觉推理和文档检索 rerank。
Query reformulator / retrieval agent 查询改写、检索轮次、过滤条件 下游召回、答案正确性、成本惩罚 中需要严格成本和越权检索约束。

上线原则：没有稳定 candidate generator、离线 reward 与线上业务指标相关性、反作弊 judge、人工抽检和延迟预算，就不要把 RL 接入生产检索链路。RL 的第一批收益应发生在 reranker 或 retrieval policy，而不是直接改向量空间。

06 / OPD

OPD：适合有轨迹的多模态决策面

OPD 解决的问题可以概括为：SFT 在 teacher 或数据集前缀上学习，学生部署后却在自己的状态分布上生成；这种 distribution drift 会让后续 RL 或推理轨迹不稳定。OPD 让 student 先在自己的轨迹上 rollout，再由 teacher 在这些状态上给更密集的 token 级或步骤级反馈 [S13][S14]。

为什么 OPD 不是 dense embedding 的直接替代

dense embedding 模型通常不生成 token 轨迹，训练目标也不是“下一个 token”。因此，OPD 无法像作用于语言模型那样直接作用于一个纯向量编码器。若要把 OPD 用到 embedding 系统，通常需要引入一个会生成的中间面：query reasoner、caption/attribute generator、generative reranker、检索代理或 teacher model。OPD 先改善这个中间面的状态分布，再把结果转成 pair、hard negatives、teacher scores 或 reasoning-conditioned inputs，最后仍用对比学习或蒸馏训练 embedding。

OPD 对多模态 reranker 的价值

PRISM 将多模态训练链路写成 SFT 到 OPD pre-alignment 到 RLVR，目标是缓解 SFT 到 RL 时的分布漂移 [S15]。Vision-OPD 则把教师和学生放在不同视觉信息条件下，用 crop-conditioned teacher 指导 full-image student rollout，针对细粒度视觉理解做在策略蒸馏 [S16]。二者共同说明：OPD 的有效面不是“任何模型”，而是有可观察轨迹、有 teacher feedback、有分布漂移的多模态决策过程。

适合 OPD 的场景

  • 视觉问答式 rerank：模型需要解释为什么某个候选能回答 query。
  • 文档页检索：模型需要在表格、图章、版式和文字之间定位证据。
  • 商品比较：模型需要生成属性差异、替代关系和排序理由。
  • SFT 到 RLVR 过渡：学生 rollout 与 SFT 数据分布差距很大。

不适合直接 OPD 的场景

  • 只输出固定维度向量，且没有可生成的中间状态。
  • 业务标签只是 pair 正负，reward 尚未校准。
  • teacher 无法稳定评价学生轨迹，或 teacher 与线上目标冲突。
  • 主要瓶颈是数据清洗、负例挖掘、索引刷新和服务成本。

07 / Recipes

落地配方：四条可执行训练链路

实际团队不应从算法名开始，而应从数据形态、服务延迟、候选规模和评测预算开始。下面四条配方覆盖最常见的生产场景。

配方 A：领域多模态 dense embedding

目标提高一阶段或二阶段召回，覆盖图文、商品、文档页、视频片段等候选。

  1. 构建任务说明：每个样本明确是同款、同义、可回答、同事件、同风格还是同属性。
  2. 整理 pair/triplet/list 数据：保留来源、时间、类目、语言、模态、人工置信度。
  3. 先训练 instruction contrastive baseline，再引入 hard negatives 和 teacher score distillation。
  4. 如果服务需要多成本档位，加入 MRL 并在多个向量维度上分别验证。
  5. 上线前评估 Recall@K、类目长尾、跨模态 query、噪声标题、OCR 错误、视觉反事实和 ANN latency。

适用证据：VLM2Vec、VLM2Vec-V2、Qwen3/Qwen3-VL、Gemini Embedding 2 [S01][S02][S03][S04][S09]。

配方 B：多模态 reranker

目标在固定候选集上提升 NDCG、MRR、top-1 精度和答案可用性。

  1. 从 embedding 或现有召回系统收集真实候选集，不用离线随机负例替代线上候选分布。
  2. 训练 cross-encoder 或 generative reranker：输入 query、候选文本、图像、页面或视频片段，输出 score、yes/no logits 或 listwise order。
  3. 用 SFT 固定输入格式、证据引用和排序理由；再视 reward 稳定性引入 RL。
  4. 把 reranker 的困难样本和软分数蒸馏回 embedding，形成召回与重排协同闭环。

适用证据：Qwen3 reranker、Qwen3-VL reranker、MM-R5、Pailitao-VL [S03][S04][S06][S08]。

配方 C：视觉文档 late interaction

目标处理 PDF、扫描件、票据、合同、表格、幻灯片和复杂页面。

  1. 先判断 OCR text pipeline 是否足够。如果文本结构完整，late interaction 不是默认选择。
  2. 对页面图像生成多向量表示，保留布局和局部视觉证据，使用 late interaction 做 query-page 匹配。
  3. 把页面级召回接入 reranker，由 reranker 负责跨页比较、证据定位和答案可用性判断。
  4. 重点监控 index size、查询延迟、页面压缩、图像分辨率和视觉证据丢失。

适用证据：ColPali 和视觉文档检索路线 [S05]。

配方 D：OPD 插入 SFT 与 RLVR 之间

目标当 reranker 或检索代理在 SFT 后进入 RL 时，用 OPD 缓解学生状态分布漂移。

  1. 用 SFT 学会候选比较、视觉证据描述、查询分解、引用格式和安全边界。
  2. 让 student 在真实候选集或困难集上 rollout，而不是继续只看 teacher demonstrations。
  3. teacher 在 student 的轨迹上给 token、step、evidence 或 preference feedback。
  4. OPD 后再接 RLVR 或 ranking reward，最后把提升样本蒸馏回 reranker 或 embedding。

适用证据：OPD 机制、OPD survey、PRISM、Vision-OPD [S13][S14][S15][S16]。

08 / Evaluation

评测、风险与上线门槛

多模态检索的评测最容易被单一指标误导。一个 embedding 模型可以在图文检索 benchmark 上表现很好，却在商品同款、视觉文档问答、长尾类目或多语言 query 上失败。一个 reranker 可以提高离线 NDCG，却因延迟、candidate mismatch 或 judge leakage 无法上线。

评测矩阵

层级 必须指标 诊断指标 失败信号
Embedding Recall@K、MRR、NDCG@K、跨模态 holdout、跨语言 holdout。 hard-negative 命中率、false negative 审计、MRL 维度退化、ANN recall loss。 随机负例提升显著但线上 top-k 无改善；文本字段变化导致视觉检索崩溃。
Late interaction page-level Recall@K、视觉文档 query NDCG、证据页命中。 index size、page token 数、分辨率敏感性、OCR-free 与 OCR-assisted 对比。 指标提升来自页面模板记忆，成本却超过 reranker 预算。
Reranker NDCG@K、top-1 accuracy、MRR、校准误差、延迟。 同屏多样性、listwise swap 错误、候选分布漂移、teacher-student gap。 离线榜单提升但真实候选集上退化；理由文本正确而排序错误。
RL/OPD 相对 SFT baseline 的稳定增益、reward-业务相关性、人工偏好审计。 judge hacking、轨迹长度、格式奖励占比、视觉证据引用准确率。 模型学会讨好 reward，但视觉 grounding 或用户目标变差。

数据和实验卫生

  • 时间切分：商品、文档、视频和 query 分布会漂移。训练、验证、测试至少需要时间切分，不能只做随机切分。
  • 类目切分：同类相似负例要进入验证集。只在训练类目内验证，会高估泛化。
  • 模态消融：分别屏蔽文本、图像、OCR、视频帧、音频，检查模型是否依赖捷径。
  • teacher 审计：teacher score 不是事实。需要抽样人工复核，并记录 teacher 与业务目标冲突的样本。
  • 成本约束：所有指标都要带延迟、QPS、索引大小、显存、批处理吞吐和刷新频率。

上线门槛

离线通过

  • 新模型相对强 baseline 在目标任务有稳定提升。
  • hard-negative、跨类目、跨语言、跨模态 holdout 无显著退化。
  • MRL 或压缩维度满足成本档位。
  • reranker 延迟、batch size 和超时策略可上线。

线上通过

  • 灰度 A/B 与业务主指标、护栏指标方向一致。
  • query 分布、类目分布和候选分布与训练评测可解释。
  • 失败样本能回流到 hard-negative 和 reranker 蒸馏流程。
  • 回滚、索引刷新、模型版本和数据血缘可追踪。

最小可发布标准：embedding 至少要证明召回泛化；reranker 至少要证明候选集内排序提升和延迟可控；RL/OPD 至少要证明相对 SFT baseline 的真实增益，而不是只证明训练曲线或 reward 上升。

09 / Decision Tree

决策树与资料索引

下面的决策树把本文判断压缩成执行顺序。大多数团队应先完成数据、对比训练、难负例、reranker 蒸馏和评测，再考虑 RL/OPD。

问题 如果是 如果不是
主要瓶颈是召回覆盖不足吗？ 先做 instruction contrastive tuning、hard negatives、合成 query 和 reranker distillation。 不要先改 embedding，检查 rerank、候选生成和业务排序目标。
候选集内 top-k 顺序错误明显吗？ 训练 cross-encoder 或 generative reranker，先 SFT，后续再看 RL。 继续优化召回、多样性或 query understanding。
模型需要生成解释、查询分解或检索动作吗？ 可以考虑 OPD 或 RL，因为存在轨迹和 teacher feedback。 OPD 通常不是第一优先级。
文档页视觉布局是关键信号吗？ 评估 ColPali 式 late interaction 或多向量检索。 单向量 embedding 加 reranker 可能更经济。
离线 reward 与线上目标相关吗？ 小规模 RL/OPD 灰度，配合人工审计和成本护栏。 先校准评测，不要用 RL 放大错误目标。

推荐路线图

  1. 第 0 周：定义任务口径，建立 source map、数据血缘、验证集和线上候选采样。
  2. 第 1 到 2 周：训练或接入 baseline embedding，完成 task instruction、hard negatives、跨模态 holdout。
  3. 第 3 到 4 周：训练 reranker，建立 embedding-reranker 蒸馏闭环。
  4. 第 5 到 6 周：对文档页或视觉商品引入 late interaction、listwise rerank 或 attribute reasoning。
  5. 第 7 周以后：只有当生成式 rerank 或检索代理成为瓶颈，并且 reward 已校准，才引入 RL/OPD。
