01 · Executive Summary

执行摘要：成熟路线与公开空白

七个平台公开材料呈现的技术图景并不整齐。淘宝、京东、抖音电商相关团队、Amazon 与 Shopee 已公开能落到具体链路的系统工作；PDD 与 SHEIN 可核验的资料更多涉及平台披露和推荐治理。证据不对称意味着比较必须先比较公开程度，再比较算法方向。

SEARCH

生成能力先进入搜索

查询改写、查询推荐、语义匹配和购物问答有明确输入、相关性评价与回退链路，较适合承载大模型。淘宝、京东和 Amazon 都给出了直接证据。[S02][S04][S07][S12-S13]

VISION

多模态的价值在商品 grounding

图搜和个性化搜索要求图像、标题、属性与行为落到可检索商品。京东实时图搜、Amazon 产品搜索、淘宝 KARMA 分别覆盖索引、训练与个性化对齐。[S03][S05][S14]

RECOMMENDATION

主链路仍讲吞吐与约束

淘宝 SORT-Gen 在重排层生成列表，抖音 ADS 在排序模型中处理跨域序列；两者都保留实时系统与业务约束，而非以通用聊天模型替换整条推荐链路。[S01][S08]

ALIGNMENT

后训练需要业务奖励闭环

京东把相关性引入多阶段训练及归一化 GRPO；Shopee 研究排序器指导的对齐；Rufus 使用反馈改进回答。业务目标必须进入训练或评价。[S07][S12][S20][S27]

本文的核心判断
可落地的电商生成式系统通常从一项可度量任务切入：视觉检索、查询改写、重排、广告内容摘要或购物问答。它们把大模型的语义能力接到既有索引、排序、库存、合规与实验系统中；公开材料没有支持“一个通用模型接管整个电商决策链路”的结论。
02 · Constraints and Architecture

电商算法的约束决定模型形态

商品系统同时面对意图表达不完整、目录高速变动、图文信息不一致、转化反馈稀疏和强业务约束。大模型能够改善语义表示与生成决策，但只有被压入低延迟、可回退、可实验的系统边界后，才具备线上意义。

五项工程约束

约束电商中的表现模型设计含义公开证据
查询不完整短 query、口语化需求、长尾表达无法准确命中商品。查询改写与查询推荐需要相关性守门和商品 grounding。淘宝 BEQUE/AIGQ；京东 LLM 改写 [S02][S04][S07]
商品是多模态对象图片、标题、规格、属性、评论共同决定可购性。内容编码器须保留可检索、可解释的产品语义。京东图搜；Amazon MML-TP；淘宝 KARMA [S03][S05][S14]
目录与库存会变上新、下架、价格与履约状态持续变化。离线语义模型仍需实时索引、过滤和服务更新。京东图搜的增量索引 [S05]
反馈带偏差曝光位置、促销、广告与历史推荐共同改变点击及成交。奖励不能只追点击；列表生成需处理多目标与反事实偏差。SORT-Gen、ADS [S01][S08]
延迟与治理硬约束大流量服务、广告标识、个性化设置、内容与商品安全。蒸馏、缓存、分阶段服务、审计与回退不可省略。Amazon 商品搜索/Rufus；SHEIN 政策 [S12-S13][S22-S23]

判断路线成熟度的尺度

一项工作若只展示生成样例，尚不能回答电商落地问题。更有信息量的材料会同时说明输入是什么、怎样关联真实商品或广告、在线服务是否有延迟边界、如何与旧召回或排序合并，以及实验究竟改善了相关性、点击、成交还是收入。本文的公司比较按这五个问题展开。

03 · Multimodal and Visual Retrieval

多模态大模型与图像检索

电商图像检索的难处不在看懂一张图，而在把视觉相似、商品属性、用户意图和实时可售目录对齐。公开路线经历了从大规模图像索引、图文表征学习，到把语义保持写入个性化训练目标的推进。

三层问题与代表证据

层次要解决的问题公开实现可迁移经验
索引与检索商品图更新频繁，检索结果必须跟随上下架与新图变化。京东实时视觉搜索论文描述百亿级以上商品图与增量更新要求。[S05]先把特征抽取、分布式索引、增量刷新和过滤做稳，再引入更重的模型。
图文表示标题含促销噪声，图像与文本并非干净配对。Amazon MML-TP 以 token pruning 清理训练中的文本噪声，在超过 71 万 Amazon 商品组成的数据集上评价视觉检索。[S14]商品数据清洗是表示学习的一部分，不能完全依赖离线人工规则。
个性化对齐行为目标优化可能侵蚀预训练模型保有的商品语义。淘宝 KARMA 将多模态语义可恢复性作为训练期正则，作者报告线上 GMV 增长 0.9%。[S03]个性化损失与内容保持损失需要共同监控，防止表示只记热门共现。

生成式多模态检索的边界

Amazon 参与的 GENIUS 将图像、文本或图文对象量化为层次化离散标识，再由生成模型预测目标标识；推理时使用 trie 约束输出为有效条目。CVPR 2025 工作在多模态基准上显示了生成检索相对既有生成方法的提升，并不等价于 Amazon 商城已经用该方案替换在线商品检索。[S15]

EMBED AND RETRIEVE

向量检索

编码查询和商品，利用近似最近邻搜索取候选。索引工程成熟，新增商品可快速写入；检索目标仍受表征质量制约。

GENERATE AND VALIDATE

生成检索

将商品表示为离散代码，模型按条件生成代码，再以合法前缀树和库存规则验证。统一建模能力增强，同时引入解码成本和无效候选风险。

适用于商品图搜的实施顺序

  1. 建设稳定的商品图、主图版本、类目、属性、库存及上下架流水线，建立图搜点击和成交的可回溯日志。
  2. 以图像到商品的向量召回作为基线，分别测同款、相似款、搭配意图与长尾新品的召回质量和更新延迟。
  3. 引入图文联合编码和噪声清洗，对商品标题中的促销语、模板词和冲突属性做训练期处理。
  4. 只有在长尾泛化或跨模态查询成为主要短板时，才验证离散语义标识或生成式检索；保留 ANN 和规则候选作为回退。
04 · Post-training

后训练：让生成模型服从交易目标

电商中的模型输出会改变检索曝光、转化路径与商家收益。通用语言能力不足以约束相关性、价格事实、库存有效性和促销合规；后训练的任务是把这些可验证约束转化为训练样本、偏好关系、奖励和上线门槛。

从 SFT 到业务奖励

阶段数据与目标适合任务风险控制
领域继续训练商品属性、类目知识、查询与多语种交易表达。属性理解、客服问答、检索语义基础。去重、时效标签、禁售和敏感属性过滤。
监督微调 SFT高质量 query-rewrite、问答、摘要、推荐解释配对。查询改写、视频广告摘要、购物助手响应。答案必须可回指商品目录、政策或检索证据。
偏好优化同一输入下的优劣输出对，训练模型偏向更合适响应。对话答案、解释风格、商品比较。DPO 简化训练，但偏好标签仍可能忽略成交相关性。[S26]
奖励优化相关性、点击/成交、合规、列表价值或下游 ranker 信号。查询生成、主动推荐、列表策略。防止奖励投机，使用离线守门与小流量实验。GRPO 提供无需 critic 的组内相对优化思路。[S27]
检索增强与工具实时目录、评论、问答、库存与政策 API。购物问答、比较和决策辅助。回答引用证据、库存价格临出答案前刷新、调用审计。

公开系统如何选择奖励

淘宝 AIGQ 将首页搜索前查询推荐改为混合生成架构，论文描述了由在线点击率提供的模型奖励和近线/在线组合服务。这里的关键并非生成更自然的查询，而是生成 query 能否进入检索并改善用户行动。[S02]

京东查询重写 使用多任务 SFT 与 Query-Based Normalized GRPO，将 query 与检索商品之间的相关性纳入优化；论文称该方法自 2025 年 8 月在京东实施，并报告在线实验改善相关性和每用户购买转化。该结论按作者声明引用。[S07]

Shopee RGAlign-Rec 面向聊天入口的零查询主动推荐，把既有排序模型作为大模型推理器的奖励信号；作者报告初始 query-enhanced 推荐与后续对齐阶段的在线增益。这提供了一个实用结构：语义推理产生意图，成熟 ranker 负责判断商品价值。[S20]

Amazon Rufus 的官方说明将专门训练的购物 LLM、检索增强生成、客户反馈学习、连续批处理和流式响应放在同一系统叙述中。这表明购物助手的后训练无法脱离证据检索和服务工程独立讨论。[S12]

05 · Generative Recommendation

生成式推荐与列表决策

推荐场景要生成的对象未必是自然语言。它可以是商品的离散标识、下一次行为、完整曝光列表或列表编辑动作。生成方式改变之后，库存合法性、多目标收益和在线吞吐仍由推荐系统承担。

语义 ID 与序列建模

TIGER 先用残差量化将商品表示为语义 ID，再训练序列到序列模型依据用户历史生成下一个物品 ID；该方法为冷启动商品共享语义 token 提供了清楚接口。HSTU 则把工业推荐描述为大规模行为序列转导问题，公开论文报告了生成推荐模型在在线实验中的观察结果。这两篇方法论文说明生成式推荐为何可行，不能作为本文七家公司已部署某种系统的证据。[S24-S25]

生产系统中的两种落点

落点模型承担的决策公开案例仍需保留的工程部件
列表级重排从已有候选产生兼顾点击、转化和 GMV 的顺序列表。淘宝 SORT-Gen 报告在百亿补贴场景带来 +4.13% CLICK 与 +8.10% GMV，并称已部署于多个淘宝场景。[S01]多路召回、候选过滤、预算/库存/合规策略与 A/B 实验。
跨域序列排序在不同业务域下解释同一用户的序列行为并给候选打分。抖音 ADS 在线表报告电商场景 GMV/U +0.79%，并称部署于多个 ByteDance 推荐服务。[S08]实时行为流、特征一致性、排序服务容量和域间干扰监控。

生成召回不应被写成全面替代

向量召回对超大目录的服务路径、增量索引与回退机制已经成熟。生成式候选在冷启动、长尾与统一建模上有吸引力，却会带来无效代码、重复候选、解码延迟和目录变更同步问题。更稳健的实验路线是新增一条生成候选通道，与关键词、向量、图和运营召回融合，再由相同精排与约束层衡量增量价值。

候选 = lexical ∪ vector ∪ graph ∪ generative_SID ∪ operations
候选 = 过滤(可售状态, 合规, 去重, 预算, 已曝光, 延迟上限)
列表 = 重排(候选, CTR, CVR, GMV, 多样性, 长期价值)
上线条件 = 相关性不退化 ∧ 无效商品率受控 ∧ 延迟/成本可承受
经验判断
生成式推荐的首个可靠收益往往来自候选增量或列表重排，而不是移除已有召回和排序。前者可隔离效果、限定失败范围并保留回退；后者需要一次性承担目录覆盖、服务容量和策略治理，证据门槛高得多。
06 · AI Search

AI 搜索：从查询理解到购物助手

搜索给生成模型提供了清晰的验证对象：一条生成 query 是否检索到相关且可购的商品，一段回答是否基于目录和评论证据，一次交互是否推动用户完成决策。因此，搜索是公开材料中最密集的生成式电商落点。

四类产品能力

能力用户请求模型输出验收指标证据
长尾查询改写表述模糊、少结果 query。可检索且保留意图的 rewrite。相关性、少结果率、成交。淘宝 BEQUE、京东 LLM 改写 [S04][S07]
搜索前查询推荐尚未输入，结合会话与兴趣提示。可点击的个性化 query 列表。点击、后续检索和交易贡献。淘宝 AIGQ [S02]
语义商品匹配自然语言需求寻找商品。query/product embedding 与候选。检索相关性、在线替代品命中、延迟。Amazon 蒸馏模型 [S13]
购物对话比较、推荐、细节问答和决策辅助。有来源支撑的答案及商品入口。有用反馈、事实性、点击/转化、响应延迟。Amazon Rufus；Shopee 对话推荐研究 [S12][S20]

两种上线方式

生成内容进入旧引擎，适合查询改写与查询推荐。模型生成文字，既有搜索系统执行召回、过滤与排序；相关性模型能够拒绝偏离原意的改写。淘宝与京东论文都沿着这一路径构造反馈。[S02][S04][S07]

大模型协调检索与界面，适合购物问答。Rufus 官方工程稿描述了购物专用 LLM、来自商品目录/评论/社区问答及 Stores API 的检索增强、客户反馈学习，以及连续批处理与流式呈现。回答生成和证据刷新、组件渲染、延迟服务必须联动。[S12]

搜索相关性的防线

搜索任务中最危险的生成错误，是生成一个看似合理、实际改变购物约束的 query：颜色、尺寸、兼容型号、价格上限、禁用成分或配送承诺被省略，都会把流畅的建议变成错误商品入口。训练数据需要保留约束属性，奖励模型需要重罚约束丢失，线上还要用结构化商品属性和库存过滤做最终校验。

系统问题方法要点公开状态
BEQUE长尾 query 召回不足。LLM 生成多个改写，并借助淘宝离线系统的排序反馈对齐在线目标。工业论文记录线上 A/B 提升 GMV 与交易数。[S04]
SORT-Gen最终列表需同时优化点击、转化与 GMV。生成式列表重排，避免逐步推断的在线代价。SIGIR 2025；报告百亿补贴及多场景部署。[S01]
AIGQ首页 HintQ 需提前捕获个性化购物意图。近线个性化生成与在线轻量路径结合，使用点击反馈奖励。2026 预印本；线上结果为作者报告。[S02]
KARMA行为优化导致多模态语义坍缩。以图文语义可恢复性作为训练期正则，服务阶段不增加同类解码负担。2026 材料；作者报告线上 GMV +0.9%。[S03]

这些工作形成的共同路线是：生成模型没有绕过检索与交易指标，而是被放入查询入口、个性化表示和最终列表三个能单独做实验的节点。对团队而言，这种拆解比“训练电商通用大模型后再找场景”更容易建立指标闭环。

京东：实时图搜打底，LLM 改写进入搜索

京东 2019 年公开的实时视觉搜索系统明确了电商图搜的硬问题：大量商品图片与高频变更要求分布式特征抽取、实时增量索引和快速检索。JDsearch 又公开了来自真实查询与完整交互的个性化商品搜索数据集，包含约 17 万 用户、1200 万 商品、940 万 次真实搜索与 2600 万 条用户商品交互。[S05-S06]

2026 年查询重写预印本把 LLM 推进一步：多任务 SFT 生成改写及相关性标记，后续以 Query-Based Normalized GRPO 优化；作者称方法自 2025 年 8 月在京东实施。公开链路支持“京东将后训练用于电商搜索改写”的陈述，尚不支持其生成模型已经取代推荐主链路。[S07]

抖音电商：跨域序列排序已有直接证据

ADS 研究的是超级应用中多业务域用户序列的不同含义。论文包含 Douyin-Ecom 数据和线上实验，在线结果表报告电商场景 GMV/U +0.79%，并称方法已部署于多个 ByteDance 推荐服务。这是一条直接属于抖音电商推荐排序的公开证据。[S08]

Monolith 较早公开了 ByteDance 面对动态稀疏特征的在线训练基础设施，并声明落于 BytePlus Recommend 产品；它说明实时推荐的系统背景，不构成抖音电商直接部署证明。RankMixer 关注更大排序模型如何在高 QPS 与延迟约束下使用 GPU，报告将模型利用率从 4.5% 提升到 45% 并在抖音推荐系统部署；SUMMA 则以多模态大模型摘要视频广告内容，论文报告搜索广告收入增长 1.5%。这三项材料提供相关基础与搜广方向，ADS 仍是本文用于抖音电商部署判断的直接证据。[S09-S11]

PDD（拼多多/Temu）：公开披露不足以归纳模型路线

PDD Holdings 2025 Form 20-F 提及竞争者采用人工智能方案，并披露 Temu 的推荐系统受到欧盟监管审查等风险；文件没有说明拼多多或 Temu 的多模态模型、后训练算法、生成式推荐或图搜架构。对该集团的严谨结论限于：推荐系统处在平台合规与竞争语境内，本文未找到足以还原具体产品技术路线的一手公开论文或工程稿。[S21]

08 · Global Platforms

跨境与国际平台公开路线

Amazon 的证据从在线语义匹配延伸到购物对话，Shopee 将东南亚多语种电商能力与推荐对齐并行推进，SHEIN 则通过政策披露呈现排序因素和治理压力。三者展示了产品形态、语言市场和公开义务对技术叙事的影响。

Amazon：检索、图文表示与购物对话

Amazon 的 web-scale 语义商品搜索使用大型教师模型训练并蒸馏到 75M 参数 BERT 类在线模型，论文报告在相近推理延迟下离线相关性相对 DSSM 基线最高提升 23%，线上 A/B 对精确与替代商品检索各报告 2% 提升。这里最可迁移的经验是用大模型提供训练信号，让服务模型满足实时检索预算。[S13]

MML-TP 针对图文商品搜索中标题噪声进行在线 token 清理；GENIUS 则研究把多模态目标量化成代码后生成检索。前者直接以 Amazon 商品数据评测，后者是由 Amazon 研究者参与的通用多模态检索成果，部署含义不同。[S14-S15]

Rufus 是产品工程证据最完整的生成式购物入口：官方技术稿写明专用购物 LLM 使用目录、评论、社区问答及公开网页信息训练，并通过 RAG 调用可靠数据源和 Stores API；反馈学习、Inferentia/Trainium、连续批处理和流式 hydration 共同服务在线体验。[S12]

Shopee：多语种领域模型与排序反馈对齐

LightSAGE 是稳固基线：RecSys 2023 论文描述它在 Shopee 广告推荐中以图神经网络产生 item embedding 并进行向量检索，经在线 A/B 后部署到主流量。后续 Compass 系列把问题扩到东南亚语言与电商工作流；Compass-v3 技术报告描述了多语种、多模态电商训练，以及基于最优传输的直接偏好优化。[S16-S18]

EcomEval 给出了六大类、37 个任务、其中 8 个多模态任务的领域评价设计；RGAlign-Rec 面向聊天入口的主动推荐，用排序模型反馈约束 LLM 生成的潜在查询，并报告在线实验。把领域评测先建立起来，再将生成推理接到已有 ranker，是 Shopee 材料中最清楚的工程次序。[S19-S20]

SHEIN：可确认排序因素，无法确认模型实现

SHEIN Marketplace User Ranking Policy 声明搜索与商品列表会考虑查询匹配、浏览历史、点击、加购、购买、位置和个性化设置，并向用户提供调整个性化的入口。这份政策能确认排序及推荐因素存在，不披露算法模型、训练方式或线上收益。[S22]

欧盟委员会于 2026 年 2 月 17 日公告启动针对 SHEIN 的《数字服务法》调查，其中包括推荐系统透明度，并指出超大型在线平台必须披露推荐系统主要参数且提供不基于画像的选项。对于 SHEIN，算法团队最先能从一手材料得出的路线问题是可解释与用户控制，而非某种未公开模型的优劣。[S23]

09 · Engineering Playbook

工程实施路径与经验

公开实践支持一条稳健路线：建立可审计数据和成熟检索/排序基线，在边界明确的节点加入生成能力，再以业务与治理指标决定是否扩大范围。以下路径面向要实际建设电商算法能力的团队。

路线图：四阶段而非一次替换

不同业务切入口

业务症状优先实验训练/服务设计不应先做的事
图片找同款或相似款体验弱图文编码 + 增量向量检索。清洗图文噪声，单独测新品和上下架延迟。未经索引基线即投入生成 ID 全量替换。
长尾搜索少结果、搜索词表达差约束保留的 query rewrite。SFT 后以相关性/成交守门，小流量接入原搜索引擎。只优化语言流畅度或生成多样性。
推荐候选充足但列表目标冲突列表级重排。候选固定，评价点击、转化、GMV、多样性及约束违例。把列表问题包装成开放式聊天生成。
用户需要比较和决策辅助检索增强购物助手。目录/评论/政策检索，工具调用，事实评价和流式服务。依赖模型记忆给价格、库存或适配结论。
跨场景行为割裂域感知序列排序。分域评价，监测一个域的优化是否牺牲另一个域。直接混合所有日志当成同一偏好信号。

团队需要掌握的经验

数据先被定义为决策证据，商品目录、图片版本、搜索日志、曝光位置、价格库存和负反馈需要能沿一次推荐或搜索请求回溯。否则后训练会把历史偏差写进模型，却无法判断错误来自数据、模型还是策略。

奖励接近实际目标，也要比实际目标更可诊断，点击或成交可以用于线上判断，但训练中还需相关性、约束保留、无效商品、事实错误和多样性等分解指标。单一收益信号容易奖励误导 query 或过度曝光热门商品。

重模型放在有价值的位置，Amazon 的蒸馏语义搜索和 Rufus 服务工程、淘宝混合查询生成、抖音排序模型的服务优化，都指向相同实践：昂贵语义能力用于提供信息增量，稳定低延迟路径承担大规模曝光。

治理是模型接口的一部分，广告标识、个性化设置、申诉、内容和商品安全需要成为请求、输出或日志中的结构化字段。SHEIN 与 PDD 的公开材料虽然不能回答模型结构，却提示团队：推荐系统需要说明它对用户做了什么。

10 · Evaluation and Research Agenda

评估、风险与研究议程

生成式电商算法的评价必须把语言质量压回交易真实性与系统责任中。能写出合理文本的模型，只有在相关商品可售、约束不丢、长尾不被压制、延迟可控且用户有选择权时，才形成生产价值。

评价矩阵

环节离线核心指标线上指标失败警报
图搜/多模态召回Recall@K、类目/属性一致、冷启动覆盖。点击、加购、成交、响应和索引更新延迟。视觉相似却规格错误；已下架商品返回。
查询改写/生成相关性、约束保留、少结果率、去重。检索成功、点击、购买转化、负反馈。品牌/尺寸/价格限制消失；诱导式 query。

购物助手grounded QA、引用正确、安全和拒答。有用反馈、商品入口行为、延迟与成本。错误库存/价格/兼容性建议；不可解释来源。

常见误判

误判问题所在更严谨的做法
论文有线上数字，因此可以横向给平台排能力名次。各论文的场景、流量、基线、指标和统计检验不同。只在同一论文的对照内读提升，跨平台比较路线与证据而非数值。
公司研究者发表生成检索，即商城已上线该检索。研究基准与生产部署是两种证据。没有部署表述时写为研究方向，Amazon GENIUS 即如此。
相关业务线模型可代表目标产品。广告、Feed、商城搜索和电商推荐有不同目标及规则。抖音章节将 ADS 直接证据与 SUMMA 相关证据分列。
没有论文就说明没有技术能力。企业可能选择不公开。写为公开证据不足。PDD 与 SHEIN 不作负面能力推断。
生成回复自然即可上线。电商错误会直接改变购买决策。对目录 grounding、约束保留、库存价格刷新、回退与申诉设硬门槛。

仍值得推进的研究问题

可变目录下的生成标识，新品、变价和下架频繁发生，语义 ID 或生成索引怎样快速更新且不破坏已有表示，仍需要更完整的工业证据。

多模态语义与行为收益的冲突，KARMA 已将语义坍缩问题明确提出；未来系统需要监测内容相似、个体偏好和商家生态之间的长期平衡。

奖励与合规联合建模，相关性、成交、广告透明、用户控制和公平约束如何进入同一优化流程，公开工作仍多在单任务或局部场景。

平台可解释性的技术标准，SHEIN 受到的透明度审视提示一个普遍问题：生成系统越能主动推断与组织商品，平台越需要给用户可理解、可关闭、可审计的控制面。

结论
电商大模型路线的技术判断，应从可核验的购买决策节点开始，继而确认数据、奖励、服务与治理边界；生成能力只有带来可归因的增量，才值得扩大范围。这一顺序与公开工业证据最相符。
