CHAPTER 00

执行摘要：表征先解决可比较，再解决可交互

多模态表征的核心问题不是“把图片、文本、音频、视频都塞进一个模型”。真正的问题是：不同模态的观测来自不同传感器、不同采样率和不同符号系统，模型如何把它们变成可比较、可检索、可推理、可生成、可行动的内部状态。

第一层：可比较

CLIP、ALIGN 和 SigLIP 把图像与文本放进同一个向量空间，检索和零样本分类因此变得简单 [S05-S07]。这一步解决的是“谁和谁语义接近”，不是“模型是否真的理解图像”。

第二层：可交互

BLIP、BLIP-2、Flamingo、LLaVA 把视觉状态接进语言模型，让模型能回答、解释、跟随指令 [S08-S10, S15]。这一步的代价是语言偏置会进入视觉任务。

第三层：可组合

ImageBind 用图像作为枢纽，把文本、音频、深度、热成像、IMU 等模态绑到同一空间 [S16]。4M 和 Chameleon 则尝试把输入输出都纳入统一 token 或 masked modeling 系统 [S20, S21]。

第四层：可验证

MMEB、MME、MMBench、MMMU 和 HallusionBench 指向同一个事实：表征质量不是一个分数，检索、问答、专业推理、视觉抗幻觉需要分开测 [S23, S25-S28]。

本文的主线很直接：先把表征看成任务可用的状态空间，再看训练信号如何塑造这个空间，最后把它落回工程系统。读完后，读者应该能回答四个问题：一个多模态模型的内部接口是什么；它用什么信号学到跨模态关系；它适合检索、问答、生成还是行动；它的失败会发生在数据、目标函数、连接器、评测还是产品边界。

CHAPTER 01

从 0 开始：表征不是压缩，是给任务一个可计算的状态

表征学习把原始观测转成任务能使用的状态。好的表征保留任务需要的变化，丢掉任务不关心的扰动。多模态表征再往前走一步：它要让来自不同模态的状态能互相参照。

一个表征至少要回答三件事

第一，相似性如何定义。图像里两只不同角度的狗、文字里“dog”和“puppy”、音频里的犬吠，原始信号相差很大，但下游任务可能希望它们靠近。第二，不变性如何选择。分类任务希望光照变化不改变类别；医学图像任务可能不能随便丢掉亮度和纹理；机器人任务还要保留空间、姿态、速度。第三，接口如何暴露。一个向量可以做检索，一个 token 序列可以接进语言模型，一个时序 latent 可以接控制策略。

早期视觉语义嵌入已经把问题摆出来。DeViSE 把视觉模型输出映射到文本语义嵌入空间，用语义空间支持零样本识别 [S01]。这条路线并不复杂，但它改变了视觉分类的边界：类别不再只是固定 softmax 里的索引，而可以被语言描述扩展。

“多模态”真正增加的是对齐约束

单模态表征只需要在一种观测里找到稳定结构。多模态表征多了一层约束：来自不同模态的样本何时应该靠近，何时应该保持差异。图片和文本描述同一个物体时可以靠近；图片里的空间布局和一句笼统 caption 却不该完全等价。音频里的节奏、视频里的动作、IMU 里的加速度和文本语义也不能被粗暴压成一个概念标签。

这也是很多多模态系统失败的来源。模型把跨模态相似性学到了，但把任务需要的局部信息丢了。一个图文 embedding 能找出“有发票截图”的图片，不代表它能读出表格里第 17 行的税额；一个视觉语言模型能描述“有人在骑车”，不代表它能稳定判断轮胎和车道线的几何关系。表征空间越通用，越要问它为哪个接口服务。

CHAPTER 02

从 1 开始：图文对齐为什么成为多模态表征的入口

图文对齐成为入口，不是因为图像和文字天然最重要，而是因为互联网上有大量图文配对，语言又能给视觉概念一个开放词表接口。CLIP 和 ALIGN 把这个判断推到规模化阶段。

CLIP 把分类器改造成语言查询

CLIP 的训练任务很朴素：一批图文对里，模型要判断哪一句文字配哪一张图。OpenAI 论文报告使用 4 亿图文对从头训练，并用自然语言描述来引用视觉概念 [S05]。这让 ImageNet 这类固定类别分类，变成“文本 prompt 与图像表示的相似度”问题。分类头不再是封闭标签集合，而是可由语言扩展的查询接口。

这个接口的工程价值很高。向量检索系统已经成熟，图文对齐模型只要输出稳定 embedding，就能进入搜索、素材管理、推荐召回、内容安全初筛、RAG 的图像检索层。它的局限也同样直接：双塔模型在编码后才比较向量，图像和文本没有在 token 级别深入交互，所以细粒度定位、复杂关系、逐步推理不是它的强项。

ALIGN 证明噪声可以被规模抵消，但不能被规模洗白

ALIGN 延续双塔加对比学习路线，重点在数据策略：用超过十亿级噪声 alt-text 图文对训练，减少昂贵清洗 [S06]。它的价值不只是“数据更大”，而是说明在开放网页语料里，规模可以抵消一部分标注噪声，简单结构也能产生强迁移。

但噪声没有消失。alt-text 带着网页作者的偏见、广告语言、缺失描述和文化分布。规模化图文表征会继承这些偏差。工程上不能只问模型在公开 benchmark 上几分，还要看业务语料里哪些概念被过度关联，哪些边缘类别被稀释，哪些安全词会把图像召回推向错误方向。

SigLIP 把“更大 batch”这件事重新拆开

标准 CLIP 式对比学习依赖 batch 内全局 softmax。SigLIP 改用 pairwise sigmoid loss，不要求对整批相似度做全局归一化 [S07]。这条改动看似是训练细节，实质上改变了扩展路径：对齐质量不只靠堆更大的 batch，也可以通过更合适的损失函数降低通信和内存压力。

工程判断，如果任务是高吞吐检索和召回，双塔仍是首选接口：离线批量编码、向量库索引、近似最近邻检索、在线延迟都清楚。只有当任务需要解释图中关系、读文档、跟随复杂指令或生成多轮答案时，才需要更重的跨模态交互。

CHAPTER 03

目标函数：对比、遮盖、预测与生成

目标函数决定表征空间的形状。对比学习让正样本靠近、负样本远离；遮盖建模要求模型补全缺失信息；预测表征不重建像素，而预测 latent；生成目标要求状态能驱动语言或图像输出。

对比学习把“相似”变成可检索结构

对比学习的强项是把大量弱标注样本转成可检索空间。只要正样本定义可靠，模型就能把语义相关的图片和文本拉近。问题在于，正样本通常来自 caption 或网页上下文，它描述的只是图像的一部分。图像里没被描述的对象、细节、位置关系，在训练信号里就是弱信号。

遮盖建模让模型不得不看上下文

UNITER 用遮盖语言、遮盖区域、图文匹配和词区对齐训练联合表示 [S04]。BEiT-3 把图像看作一种外语，用 Multiway Transformer 在图像、文本和图文对上做统一 masked modeling [S11]。4M 把这个思路推到更宽的输入输出空间，把文本、图像、几何、语义和特征图离散化后用 masked modeling 训练 [S20]。

遮盖建模的意义在于，它不只问“这张图和这句话像不像”，而是问“在这个上下文里，缺掉的部分应该是什么”。这更接近文档理解、局部定位和跨区域关系，但训练成本、数据组织和 tokenizer 误差也更难控制。

预测表征提醒我们：语言不是唯一监督

data2vec 用同一种 latent prediction 框架处理语音、视觉和语言 [S17]。I-JEPA 从一个图像上下文块预测目标块的表示，不重建像素 [S18]。V-JEPA 在视频上用特征预测学习视觉表征，论文明确强调不使用预训练图像编码器、文本、负样本、重建或其他监督 [S19]。这条线对多模态很重要，因为它把表征学习从“必须借语言监督”里拉出来。

语言仍然是最方便的人机接口，但它不是所有感知任务的自然标签。机器人、自动驾驶、医学影像、工业检测、长视频理解都可能需要保留语言描述之外的物理和时间结构。把一切压进文本相似性，反而会丢掉这些结构。

CHAPTER 04

结构谱系：双塔、跨注意力、桥接器和早融合

同样叫多模态模型，结构差别很大。双塔适合离线编码和检索，跨注意力适合理解细节，桥接器适合复用大语言模型，早融合适合把混合模态文档当作同一种序列建模。

跨注意力解决局部关系，代价是重

ViLBERT、LXMERT、UNITER 这一代视觉语言预训练模型，把视觉区域和文本 token 放进互相交互的 Transformer 结构里 [S02-S04]。它们处理的是双塔不擅长的问题：词和区域如何对齐，问题里的关系词如何落到图像对象上，图像上下文如何影响语言理解。

这类模型更像“读图”，而不是“查找相似图片”。缺点是在线成本高。每次查询都要让文本和视觉 token 交互，无法像双塔那样把图片离线编码后直接走向量索引。它适合 VQA、视觉推理、文档局部理解，不适合作为大规模召回第一层。

桥接器是大语言模型时代的现实主义

BLIP-2 直接承认端到端预训练大模型成本太高，于是冻结图像编码器和 LLM，用轻量 Q-Former 桥接两者 [S09]。Flamingo 用 Perceiver Resampler 接收视觉输入，并让语言模型处理交错图文序列 [S10]。LLaVA 用视觉编码器、投影连接器和视觉指令数据，把图像接进对话式 LLM [S15]。

这条路线快，复用语言模型的知识、推理和指令跟随能力。但它也把语言模型的先验带进视觉任务。模型可能回答得很像“懂了”，但视觉证据并不支持。HallusionBench 这类诊断集存在的原因，正是要把语言偏置和视觉证据的冲突暴露出来 [S28]。

对比加生成，把 embedding 和 caption 放回一张图里

BLIP 用 captioner 和 filter 改善网页噪声图文对，把理解任务和生成任务放进同一框架 [S08]。CoCa 同时使用对比损失和 captioning 损失，尝试让一个图文 encoder-decoder 同时服务视觉识别、跨模态检索、多模态理解和 caption [S12]。这类模型的关键取舍是目标之间是否互相帮助：检索要稳定相似度，生成要足够表达，二者共享骨干时会争夺容量。

CHAPTER 05

从图文到全部：ImageBind、4M、Chameleon 与原生多模态

“全部模态”不是把输入类型越堆越多。真正困难的是，不同模态之间不一定两两配对，采样率不一致，token 化方式不同，输出目标也不同。当前公开路线大致分三类：枢纽空间、any-to-any masked modeling、mixed-modal early fusion。

ImageBind：用图像作为跨模态枢纽

ImageBind 学习一个包含图像、文本、音频、深度、热成像和 IMU 的共享嵌入空间 [S16]。它的关键判断是：不需要所有模态两两配对，只要每种模态都能和图像配对，就可以通过图像枢纽把空间绑定起来。这个设定很工程化，因为现实数据里“视频加音频”“图像加深度”“图像加 IMU”比任意两模态配对更常见。

枢纽空间也有边界。图像决定了很多语义锚点，适合视觉中心任务；但如果任务核心关系发生在音频和文本之间，或者在 IMU 和动作策略之间，图像枢纽可能只提供间接约束。所谓 emergent alignment 要放在任务里看，不宜直接写成任意模态之间都等价连通。

4M：把多种输入输出统一进 masked modeling

4M 训练一个统一 Transformer encoder-decoder，用 masked modeling 处理文本、图像、几何、语义和神经网络特征图等多种输入输出 [S20]。这条路线关心的是 any-to-any：任意模态子集作为条件，预测或生成另一组模态。它的优势不是检索延迟，而是任务灵活性。比如一套模型可以从图像预测深度、从语义预测图像、从文本控制编辑。

这类模型最依赖 token 化质量。模态被离散化后，模型学到的是 token 序列的统计结构；如果 tokenizer 把空间、纹理或时间切碎得不合适，后面的 Transformer 再大也只能在失真的单位上推理。

Chameleon：早融合把混合文档当作同一种序列

Chameleon 把文本和图像都表示为 token，在同一个 early-fusion Transformer 里处理和生成任意交错的图文序列 [S21]。这条线的吸引力很强：它不再把视觉当成 LLM 外面的附件，而是把多模态文档建模为统一序列。

早融合的问题也更硬。训练稳定性、tokenizer、上下文长度、混合输出质量、推理成本都会变成一体化问题。工程上如果只需要图片检索，早融合是过度设计；如果要生成真正交错的图文内容，或者要在一个上下文里让输入和输出都混合模态，早融合才有必要。

闭源原生多模态是产品信号，不是架构证据

GPT-4V system card 披露的是视觉能力边界、风险和安全缓解，而不是完整模型结构 [S29]。GPT-4o 产品页展示文本、音频、图像更自然地进入同一交互界面 [S30]。这些产品信号说明多模态正在从“上传图片问答”走向“实时、多轮、跨输入输出”的系统体验，但公开材料不足以判断内部表征是共享向量、桥接 latent、统一 token 还是混合路线。

CHAPTER 06

评测：embedding 好、问答好、推理好是三件事

多模态评测不能只看一个总分。检索 embedding、视觉问答、专业推理、抗幻觉、长视频理解、文档解析，测的是不同接口。把它们混成一个排名，会掩盖模型真实能力边界。

评测要和接口一致

一个图文双塔模型可以在 retrieval 上很强，但它不该被要求直接做复杂多轮推理。一个视觉语言模型可以在 VQA 上强，但它的 embedding 可能不适合向量库召回。VLM2Vec 的价值在于把“视觉语言模型能不能转成 embedding model”单独拿出来测 [S23]。这提醒工程团队：不要把 chat model 的截图问答能力当成检索表征质量。

专业推理暴露的是组合能力，不只是视觉能力

MMMU 覆盖 6 个学科、30 个 subjects、183 个 subfields 和多种图像类型 [S27]。这类评测把“看得见”与“会推理”绑在一起。模型要读图表、化学结构、地图、音乐谱、医学图像，还要调用专业知识。只靠更大的图文对齐语料，不一定能解决这种组合问题。

视觉幻觉通常发生在语言太强的时候

HallusionBench 关注的是图像上下文推理和视觉幻觉 [S28]。很多错误不是模型完全没看图，而是语言先验太强：题目像某个常见模式，模型就顺着常见答案说下去。对多模态表征来说，这是一条重要边界：语言空间让视觉可问答，也可能覆盖视觉证据。

上线前的最低评测集，检索系统测 Recall、nDCG、hard negative 和长尾类别；问答系统测 OCR、表格、位置关系、否定问法和拒答；文档系统测来源定位、数值抽取和跨页引用；视频系统测时间定位、事件顺序和长间隔记忆。单一 leaderboard 不能替代业务评测。

CHAPTER 07

工程落地：如何选模型、训数据、上线和监控

工程上先选接口，再选模型。接口决定延迟、成本、可解释性和可测试性。多模态表征项目失败，常常不是模型不够大，而是一开始把检索、问答、生成、行动混成了同一个需求。

先按任务选结构

任务优先结构原因不要先做什么
图片/视频/商品召回双塔 embedding可离线编码，向量索引成熟，成本可控不要先接重型 MLLM 做在线逐条判断
文档截图问答桥接器 VLM 加 OCR/解析器需要语言接口，也需要可核验来源不要把 VLM 输出当作唯一事实来源
图表/表格理解VLM 加结构化抽取视觉布局和数值关系都重要不要只测 caption 分数
跨传感器机器人感知枢纽空间或预测表征需要图像、深度、IMU、动作状态共同约束不要把文本描述当作全部状态
混合图文生成早融合或 any-to-any输入输出都混合模态，需要统一序列建模不要用检索 embedding 冒充生成状态
推荐排序工业 embedding 加业务特征线上目标、延迟和特征稳定性比论文分数更重要不要只看公开检索 benchmark

数据比结构更早决定边界

图文数据的 caption 覆盖什么，模型就更容易学到什么。网页 alt-text 强调对象和场景，但弱化空间关系、数量、细节和否定。文档截图数据强调布局和文字，但不一定覆盖真实业务里的模糊扫描、遮挡、手写、低分辨率和跨页引用。视频数据还多了采样率、关键帧、事件边界和音画不同步问题。

训练数据应按错误成本组织。检索任务要准备 hard negatives，比如同款不同颜色、相似包装、同一场景不同动作。文档任务要准备数值相近但含义不同的字段。视频任务要准备时间相邻但事件不同的片段。机器人任务要准备同一语义下动作后果不同的状态。

冻结、微调和蒸馏的取舍

冻结 backbone 加轻量连接器，适合快速验证和成本受限场景。BLIP-2 这类路线说明，冻结强视觉编码器和强 LLM 后，用 Q-Former 桥接也能获得强能力 [S09]。全量微调适合分布差异很大、误差成本高、数据足够且需要深度适配的场景。蒸馏适合把重模型的判断迁移到轻模型，尤其在推荐、搜索、广告这类高吞吐系统里。

PinCLIP 的工业信号很有代表性：多模态 VLM 进入推荐和检索系统时，会遇到训练目标和 serving 效率不一致的问题，因此需要为内容粒度、邻居关系和线上目标重新组织表征 [S24]。这类经验不能直接推广成所有系统的最佳实践，但足以提醒团队，不要把实验室 embedding 原样塞进线上排序链路。

上线监控看五个指标族

召回指标，看 Recall、nDCG、长尾类别覆盖和 hard negative 错误；理解指标，看字段抽取、定位、引用和否定问法；生成指标，看忠实度、拒答、来源一致性和格式稳定性；系统指标，看编码吞吐、索引更新、向量漂移、缓存命中和 p95 延迟；安全指标，看隐私泄露、敏感图像误判、跨模态 prompt 注入和语言偏置。

CHAPTER 08

常见误区与前沿问题

多模态表征的成熟，不会表现为一个模型吃掉所有任务。更现实的方向是：不同表征接口被组合进同一个系统，检索层、理解层、生成层和行动层各自有可验证边界。

误区一：把共享空间当成理解

共享空间能说明样本相似，不能说明模型知道因果、数量、物理关系和任务目标。CLIP 式 embedding 可以找相似图片，但“狗在沙发左边还是右边”“图中有几颗药片”“发票税额是哪一栏”都不是相似度问题。需要局部推理时，要么引入跨注意力和结构化解析，要么把问题拆成检测、OCR、表格解析和语言推理的组合系统。

误区二：把语言当成所有模态的真值

语言是强监督，也是强偏置。caption 只描述作者认为值得描述的内容，不描述背景噪声、缺失细节、危险边界和物理状态。data2vec、I-JEPA、V-JEPA 的价值在于提醒我们，表征可以从观测之间的预测关系中学习，而不必总是把文本当作老师 [S17-S19]。

误区三：用一个 benchmark 做采购和上线决定

MMBench、MMMU、HallusionBench 这类评测各自有用途 [S26-S28]。它们可以筛模型，不能替代业务评测。真实系统里，错误成本往往集中在少数边界：低清扫描件、长尾商品、跨语言命名、相似 SKU、医学异常、儿童安全、法律和财务数字。上线前最该做的是把这些边界做成固定回归集。

接下来最值得看的问题

时间表征，长视频、实时音频和动作序列要求模型保留事件顺序、持续时间和因果关系；空间表征，机器人、AR、自动驾驶和文档理解都需要比 caption 更细的几何状态；多语言表征，PaLI 和 Qwen2.5-VL 说明多语言和文档场景已经进入主线 [S13, S22]，但低资源语言、地区视觉语义和文字系统仍难测；安全表征，系统卡和幻觉评测提示多模态风险不是文本安全的简单扩展 [S28-S30]。

一句话收束，多模态表征不是“让模型看到更多东西”，而是把更多观测变成任务可验证的状态。能检索、能回答、能生成、能行动，是四种不同能力；把它们分清楚，系统才有机会稳定。
