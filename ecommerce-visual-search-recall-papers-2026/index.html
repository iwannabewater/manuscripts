01 · 执行摘要：先读哪几篇

如果目标是建设一个可上线的电商图搜召回系统，论文优先级不应按发布时间排序，而应按“能否进入线上链路”排序。本文建议把论文分成三层：第一层是可直接指导召回主链路的工业方法，第二层是能补强召回质量或融合策略的方法，第三层是适合作为 baseline、teacher、benchmark 或下一代方向的研究。

S 层：优先精读

Pailitao-VL、TIGER-FG、TGQ-Former、UniECS、Target Text-Image Fusion。共同特点是：问题定义贴近电商，指标不是只停在通用 benchmark，且方法能落在 embedding、ANN、rerank 或多入口检索中的明确位置。

A 层：强工程参考

OneRetrieval、Efficient Generative Retrieval、Unified LTR、AFMRL、MOON、Qwen3-VL、Amazon MIM、MIEM、MAKE、Taobao V+L Retrieval。它们分别补齐多通道、生成式、属性增强、工业基线和强 teacher。

B/C 层：观察与补充

FashionMV、RMIR、MagicLens、VLM2Vec、ColPali、CLIP/SigLIP、弱监督商品检索、跨域 CBIR、多语种商品召回。这些工作不一定能直接上线图搜召回，但能指导数据、评测、迁移和下一代需求。

最重要的判断

电商图搜召回在 2026 年的有效路线不是单一模型替换，而是一个分层系统：基础层用领域双塔或 ID-supervised embedding 做稳定高召回；抗噪层用文本引导视觉 token、目标区域约束和 hard negatives 修复商家图噪声；融合层用多通道 LTR 或统一多入口模型合并候选；高精层用 MLLM/listwise reranker、属性生成和 generative recall 做增益通道。任何一篇论文如果不能说明它落在哪一层，就不应被直接作为线上改造方案。

02 · 评价框架：什么叫图搜召回能 work

本文不把“能 work”定义为单个离线 benchmark 的最高分。电商图搜召回的生产约束更苛刻：query 可以是随手拍、裁剪图、截图、商详图、短文本、图文组合；候选库是亿级商品，类目分布极不均衡；线上目标不是单纯相似，而是相关、可买、价格合理、库存可售、可解释、可回滚。

最小可行召回目标

Given query q and catalog I, retrieve C_K(q) = TopK_i s(E_q(q), E_i(i)), then merge C(q)=union_m C_K^m(q). Production objective = maximize online value under latency, coverage, freshness, diversity and safety constraints.

论文若只优化 Recall@K，还需要回答四个工程问题：召回候选是否可售，是否覆盖长尾，是否能在索引刷新后稳定，是否能被下游 ranker 消化。

04 · 主干一：双塔、多模态融合与 ANN

双塔召回仍是工业图搜最稳的第一阶段主干。原因不是双塔表达能力最强，而是它满足召回系统最关键的三个约束：item embedding 可离线预计算，ANN 检索可横向扩展，线上 query path 可控。CLIP、SigLIP、MAKE、Amazon MIM、MIEM、Target Text-Image Fusion、UniECS 都是在这个骨架上做领域化增强。

基础对比学习

z_q = normalize(E_q(q)), z_i = normalize(E_i(i)), s(q, i)=z_q^T z_i / tau. L_NCE = -1/B * sum_j log exp(s(q_j, i_j+)) / sum_l exp(s(q_j, i_l)). L_SigLIP = -sum_(q, i) log sigmoid(y_qi * z_q^T z_i + b), y_qi in {+1, -1}.

InfoNCE 适合 in-batch negatives 和大规模召回训练；SigLIP 的 pairwise sigmoid 去掉全局 softmax 归一化，适合大批量图文对齐。电商场景的关键不在公式本身，而在负样本：同类不同款、同款不同拍摄、标题相似但属性反转、图片相似但用途不同，必须被显式加入训练。

Target Text-Image Fusion：最稳的 text-only 升级路线

Target 的 2026 v2 论文选择了一个非常工程化的策略：不把 query tower 变重，而是在 item tower 内融合商品标题和图片，再把融合后的 item embedding 预计算进既有 CPU ANN 服务。方法上，它先做 domain-specific fine-tuning，再做 query-to-text 和 query-to-image 的 modality-specific alignment，最后用 MoE+Bilinear 融合商品图文表示。

这一设计的优点很明确：线上 query path 仍像 text-only 双塔一样轻，图片编码和 bilinear 交互都在离线 item encoding 阶段完成。论文报告 20M query-item pairs 训练，nDCG@1 desirability 相对 text-only baseline +4.86%，relevance +2.36%，并保持 commodity CPU-based ANN 基础设施约 2000 QPS 的服务形态 S07。

图文 item tower 的可实现结构

h_t = E_text(title, attributes), h_v = E_img(product_image). g = softmax(W_g [h_t; h_v; h_t * h_v]), h_mix = sum_m g_m * Expert_m(h_t, h_v). h_item = normalize(MLP([h_mix; Bilinear(h_t, h_v)])); ANN index stores h_item.

实现上可以先不上复杂 bilinear：第一版用 text embedding、image embedding 和简单门控拼接即可，关键是保证 item embedding 离线刷新、query embedding 延迟不变、线上召回结果能回放评估。

Amazon MIM 与 MIEM：图搜不是纯视觉相似

Amazon MIM 的贡献在于把 image-to-image matching 从低层纹理相似推进到图文语义约束：3-tower 用商品标题约束图像匹配，4-tower 再加入用户 reformulation text。论文报告 3-tower 带来 image matching CTR +4.95%，4-tower 进一步 +1.13% S12。Shopee MIEM 同样说明，仅靠图片相似会遗漏商品语义，Transformer-powered multimodal item embedding 在图搜平台部署后带来 clicks/user +9.90% 和 orders/user +4.23% S15。

这两篇的长期价值是给出一个朴素但稳定的原则：电商图搜召回要学习“商品意图”，不能只学习视觉纹理。对用户拍图而言，用户想要的可能是同款、近似款、同功能、同风格或同价格带；标题、类目、品牌、属性和点击日志是区分这些意图的关键监督。

05 · 主干二：细粒度 grounding 与抗噪视觉 token

电商图搜的难点不是“图片和商品标题是否语义相似”，而是“用户截图里的目标物是否能从全图商品、背景、模特、海报字、配饰和商家模板中被正确对齐”。TIGER-FG 和 TGQ-Former 都在解决这一问题，只是入口不同：TIGER-FG 面向裁剪图 query 到图文 item，TGQ-Former 面向商品 I2I embedding。

TIGER-FG：不做显式检测，也要让 item 表征聚焦目标区域

TIGER-FG 的问题定义非常贴近图搜：query 是用户裁剪的目标区域，item 是完整商品图加结构化文本。传统检测 pipeline 可以先定位目标再召回，但有检测成本和误差传播；CLIP-style encoder 虽快，却容易被背景和无关物品干扰。TIGER-FG 的核心是用 item text 作为语义指导，让 item embedding 在不显式检测的情况下聚焦目标区域。

TIGER-FG 的训练目标

L_v2t = 1/2 [L_NCE(z_box -> z_text) + L_NCE(z_text -> z_box)]. L_i2v = L_pos_i2v + lambda_h * L_hard_i2v, where hard negatives are mismatched texts fused with the same image. L_SRD = 1/B * sum_j KL(softmax(A_teacher_box_j) || softmax(A_student_box_j)). L_q2i = 1/2 [L_hard(q -> item) + L_NCE(item -> q)], L = lambda_dual(L_q2i + L_SDD) + lambda_item L_item.

直觉是：先把目标区域和文本对齐，再用目标区域作为 anchor 拉住融合后的 item embedding，同时用 teacher distillation 保留局部空间结构。它不是简单“加文本”，而是把文本变成视觉聚焦的约束。

论文报告在自建 ECom-RF-IMMR 上，TIGER-FG 相比最强基线 Qwen3-VL-Embedding-2B，normal 场景 Recall@1 从 74.0 到 80.1，mosaic 场景从 40.8 到 75.2，分别提升 6.1 和 34.4 个百分点；query-side 仅 85.7M 参数、256 维 embedding S02。Mosaic 消融尤其重要：不做 clutter-aware training 时，mosaic Recall@1 从 75.2 降到 47.8，说明图搜召回必须显式模拟商家图和用户截图中的多主体干扰。

TGQ-Former：metadata-anchored queries 与 exploratory queries 的分工

TGQ-Former 处理的是商品 I2I 召回中的一个常见痛点：商家商品图常包含促销字、背景和摆拍噪声，直接把视觉 token 注入 LLM 或 embedding backbone，会让模型关注错误区域。TGQ-Former 使用两类 query：metadata-anchored queries 从标题、品牌、类目等结构化文本压缩得到，负责抓与商品语义一致的视觉证据；exploratory queries 是可学习 query，负责保留文本没写出的视觉细节。

TGQ-Former 的门控调制

Q_txt = Conv1D(CLIP_txt(x)) W_Q, Q_in = [Q_txt; Q_rnd]. E(v) = [E_txt_v; E_rnd_v] = HQC(Q_in, H_img). S_title = cos(f_global_img, f_global_title), beta = 2 * sigmoid(G(u)) - 1. E_tilde = E * (1 + beta), L_rr = (1/d) ||diag(C)||_2^2.

这个结构的工程意义是把“相信文本指导”和“保留视觉探索”拆开，并用 image-title agreement 做可靠性门控。它比把所有视觉 token 平均池化更适合海报图和长标题商品。

论文在约 134K test candidates 的 full-pool I2I retrieval 中，使用 Qwen3-Embedding-0.6B backbone 时，H@100 从 NoteLLM-2 的 65.19 提升到 69.13，相对 +6.04%；相对 Perceiver-Resampler 提升 8.07%。与 2B 到 4B 级 MLLM 直接编码相比，TGQ-Former 以 35.43 GFLOPs 超过 298 到 725 GFLOPs 的 MLLM baseline S03。

上线前必须补的实验

TIGER-FG 和 TGQ-Former 的离线证据强，但仍需要做四类线上前置验证：多主体截图、海报字干扰、同类不同款、拍摄视角变化。尤其要检查“文字指导”是否在品牌错标、标题堆词、类目误挂时引入系统性偏差。

06 · 主干三：原型 ID、属性、MLLM 与 reranker

当召回目标从“相似商品”进入“同款、近同款、SKU 比价、细粒度属性一致”时，普通 CLIP-style 对比学习经常不够。Pailitao-VL、AFMRL、MOON、Qwen3-VL 给出了四条不同路线：ID classification 提供绝对锚点，属性生成提供可解释细节，MOON 给出中间指标到业务指标的桥接，Qwen3-VL 提供强通用 embedding/reranker 基座。

Pailitao-VL：从相对对比学习转向绝对 ID-recognition

Pailitao-VL 的核心判断非常直接：工业图搜需要实例级精度，而 web-scale contrastive learning 更擅长概念级对齐。为了把“同款”学成稳定的绝对空间，论文用 MLLM agent 的 Plan-Propose-Organize-Review 管线清洗工业语料，构建 billion-scale semantic prototypes，再把召回训练转成超大规模分类。

原型 ID 与 additive angular margin

cos(theta_j) = normalize(W_j)^T normalize(x), class y is prototype ID. L_id = -log exp(s * cos(theta_y + m)) / [exp(s * cos(theta_y + m)) + sum_{j != y} exp(s * cos(theta_j))].

这类损失把每个高纯商品簇变成角度空间中的原型中心，比纯 pairwise contrastive 更适合同款判别。它的前提也很苛刻：ID 簇必须足够纯，新增类和长尾类必须有治理策略。

在 Pailitao-VL 的离线表格中，Pailitao-VL-Embedding 平均分 73.73，超过 Qwen3-VL-Embedding 的 65.49、TBStars-VL 的 69.55 和 CLIP-IDClass 的 70.56；listwise reranker 平均分 73.79，超过 pointwise 72.21 和 Qwen3-VL-Reranker 69.47。线上作者报告 embedding 延迟 67ms，listwise reranker 76ms，分别带来平台全流量 GMV +2%、标准化品类 GMV +6%、SKU-price comparison 场景 GMV +20% S01。

Compare-and-calibrate listwise reranker

电商图搜 rerank 的难点是候选之间常常高度相似，pointwise “yes/no” 判断会丢失相对偏好。Pailitao-VL 把候选按 chunk 并行处理，在 chunk 内做相对排序，同时输出绝对相关性分数来跨 chunk 合并。论文报告 chunkwise 把 100 query/800 pairs 的 forward passes 从 800 降到 100，latency/query 从 182.25ms 降到 75.01ms，吞吐从 5.49 q/s 提到 13.33 q/s S01。

混合 listwise 合并

For each chunk c: model returns local order r_c(i) and absolute relevance a(i) in {0,1,2,3} or calibrated score. final_score(i) = alpha * normalize(-r_c(i)) + (1-alpha) * calibrate(a(i), q, category).

实际实现中，绝对分数校准比 listwise prompt 更关键。若跨品类或跨 query 的绝对相关性漂移，chunk 内排序再好，也会在全局合并时出错。

AFMRL 与 MOON3.0：属性生成和 RL 的合理位置

AFMRL 把商品细粒度理解定义为属性生成：先用 MLLM 生成关键属性，再用属性指导对比学习，过滤 false negatives 并重加权 hard negatives；随后用 retrieval-aware attribute reinforcement，把 Recall@k 作为 reward 反向优化属性生成器。其 reward 形式是：

R(x, a) = |P_x cap topK(x, a)| / |P_x|, R_final = R(x, a) * I(valid) + eta * I(invalid). J_GRPO = E[min(r_t A_t, clip(r_t, 1-eps, 1+eps) A_t) - beta KL(pi_theta || pi_SFT)].

论文在 M5Product 和 EIPM 数据上报告 AFMRL Recall@1 54.28，高于 VLM2Vec 48.05；SFT+RL+CIT 在分类/聚类任务上 accuracy 89.13 S09。MOON3.0 进一步强调 reasoning-aware 商品表征，用属性分解、joint contrastive + RL 和 fine-grained residual enhancement 保留细节 S19。

这类方法的正确落点不是直接替换第一阶段召回，而是三处：生成高质量属性标签，构造 hard negatives，作为 reranker 或 teacher 给双塔蒸馏。原因是 MLLM 生成链路的稳定性、成本和幻觉风险都高于双塔召回。

MOON：用 exchange rate 连接召回指标和业务指标

MOON Embedding 给出的一个重要工程概念是 exchange rate：用下游 CTR model 的 AUC 增益与中间指标增益的比值，判断哪个中间指标更值得优化。论文认为 image-based search recall 在多个行业中保持正 exchange rate，能作为多模态表征优化和业务收益之间的桥梁；同时报告 Taobao 搜索广告全链路部署，整体 CTR +20.00%，新商品 +34.80%，服饰 +35.74%，底层商家 +23.03% S10。

这对自然图搜同样有启发：不要只追求离线 Recall@K，要验证图搜召回提升是否能被下游 ranker 转化。若召回新增候选在 ranker 中被系统性压低，说明 embedding 提升并未进入业务目标。

07 · 主干四：多通道召回融合与生成式召回

真实电商召回系统很少只有一路向量召回。常见结构包含倒排、语义向量、视觉向量、同款、趋势、新品、个性化、运营干预和类目专用通道。图搜召回模型再强，也需要进入多通道候选集合，并被下游融合策略消化。

Unified LTR：把 channel merge 改成 query-dependent ranking

Target 的 Unified LTR 论文不是图搜论文，但对召回系统非常关键。它把各召回通道的 top-n 候选取并集：

R_k(q) = {(i, s_k(q, i)) | i in I}, R(q) = union_k Top_nk(R_k(q)). f(q, i; theta): Q x I -> real, sort candidates by f(q, i; theta). y(q, i, week) = w_click * click + w_atc * add_to_cart + w_purchase * purchase.

论文报告用 engagement features 和 conversion-weighted labels 后，offline NDCG@8 达到 0.7994，线上 conversion +2.85%，p95 latency 低于 50ms，并部署于 Target.com S08。对图搜来说，这意味着新视觉通道上线时不要只看通道自身 Recall，而要看它在融合层中的边际贡献、去重后贡献和最终转化贡献。

UniECS：统一多入口，而不是为每个入口各训一套

UniECS 的价值在于把文本、图像、图文组合等入口统一到一个检索框架。其门控融合可以概括为：

V_attn = LayerNorm(V2T-Attention(V', T')), G_v = sigmoid(W_v [V'; V_attn; E_v] + b_v). V_g = G_v * V_attn + (1-G_v) * V'. L = L_CMAL + L_CLAL + L_IMCL.

论文在 M-BEER 上报告 text-to-image R@10 达到 0.85，高于 GME 的 0.57 和 MM-Embed 的 0.48；线上在 Kuaishou image search 和 same-style retrieval 上，平均 SCR +27.31%、CTR +2.74%、CVR +4.67%、order +6.12%、revenue +8.33% S04。它说明统一入口模型可以减少多路系统割裂，但必须在每个入口单独监控，否则某些入口可能被平均收益掩盖。

生成式召回：2026 年值得灰度，但不宜盲目替换 ANN

OneRetrieval 和 Efficient Generative Retrieval 是 2026 年电商召回的前沿信号。它们共同承认一个现实：生成式召回在工业系统中不能只证明“能生成 item ID”，还必须解决可编辑性、覆盖、beam 成本、冷启、运营干预和与下游 ranker 的目标一致性。

OneRetrieval 的 Keyword-Aligned Encoding 把 identifier position 绑定到可解释属性词，并保留 reserved slots 支持上线后新词绑定。论文报告在 Kuaishou 替换倒排分支时 order +0.710%，近乎替换全召回阶段时保持 conversion 并提升 CTR +0.821%，系统服务数亿 PV/day S05。TmallAPP 的 CQ-SID/EG-GRPO 把 semantic IDs 当作 cluster identifier，而不是 one-item-one-ID；线上 GMV +1.15%，UCTCVR +0.40%，8 GPUs 约 200 QPS、平均 40ms S06。

生成式召回的上线边界

短期最合理的形态是“补充通道”：负责语义簇、长尾、新词、运营可编辑召回，进入多通道融合层评估。只有当覆盖、重复率、beam latency、badcase、冷启和编辑一致性长期稳定后，才考虑替换传统倒排或部分 ANN。对图搜而言，生成式召回还缺少足够公开证据证明能替代 image embedding ANN。

08 · 工程 recipe：如何把论文变成召回系统

若从零建设或升级一个电商图搜召回系统，建议按“低风险主干、抗噪增强、高精 rerank、融合治理、前沿灰度”五步推进。每一步都需要能回放、能分层、能回滚。

Step 1：先建立强双塔主干

  1. 用商品图、标题、类目、品牌、结构化属性、点击/加购/购买日志构造 query-item 和 item-item 样本。
  2. 初始化可选择 CLIP/SigLIP/Qwen3-VL/VLM2Vec teacher；线上主模型优先蒸馏成 256 到 768 维 embedding。
  3. 损失使用 InfoNCE 或 sigmoid pairwise loss，加入同类 hard negatives、曝光未点击、属性反转和同图不同商品。
  4. item embedding 离线预计算，ANN 支持按类目 shard、按库存过滤、按新品增量刷新。

Step 2：补齐电商图搜特有的抗噪训练

  1. 构造用户拍图、截图、裁剪图、海报图、多主体图、模特图、背景强干扰图的测试集。
  2. 参考 TIGER-FG 做 target-anchored alignment 和 Mosaic clutter augmentation；参考 TGQ-Former 用商品 metadata 引导视觉 token。
  3. 对每类 badcase 单独建 hard negative pool，不把所有错误混在一个平均指标里。
  4. 在 query path 保持轻量：重模型用于 teacher、离线标注、rerank 或蒸馏，不直接阻塞第一阶段召回。

Step 3：为高精场景引入 ID 和 listwise rerank

  1. 若业务有同款、标品、SKU 比价，优先构建高纯 prototype ID 簇，使用 additive angular margin 或 supervised contrastive 学实例边界。
  2. 对 TopK 候选引入 listwise reranker，chunk size 控制在 8 到 12；必须有 pointwise 或 embedding fallback。
  3. 训练时加入绝对相关性标注，避免 chunk 之间只有局部排序没有全局校准。
  4. 使用 Qwen3-VL-Reranker 或 Pailitao-VL 类方案做 teacher，再蒸馏到更轻 reranker。

Step 4：用多通道 LTR 接住新增候选

  1. 每个召回通道保留 channel ID、rank、score、query/item features、freshness、库存、价格和曝光历史。
  2. 候选融合不要用固定加权长期裸跑，至少用 channel-aware GBDT/LambdaMART，训练 conversion-weighted label。
  3. 上线时看 channel marginal contribution：新增候选进入最终曝光的比例、带来的点击/加购/购买、与原通道重复率。
  4. 为新品、长尾、强视觉类目和功能类目分别设 guardrail，避免整体 GMV 掩盖局部损伤。

Step 5：把 MLLM 和生成式召回放到正确位置

  1. MLLM 属性生成优先用于数据增强、属性验真、hard negative mining、badcase 解释和 rerank teacher。
  2. 生成式召回优先作为新增通道，服务新词、语义簇和运营可编辑场景，进入融合层而不是直接替换 ANN。
  3. 对 RL 后训练使用小流量和强 guardrail：reward 同时包含 Recall、曝光质量、购买、无效候选惩罚和 KL 限制。
  4. 所有前沿模型必须有超时降级和回滚，不允许作为唯一召回来源。

09 · 稳定性地图与选型建议

不同团队应选不同路线。论文的强弱不是绝对的，关键在于商品库、入口、标注、GPU/CPU 成本、现有召回架构和业务目标。

最稳组合

在多数电商平台，最稳组合是：SigLIP/CLIP/Qwen teacher 初始化 + 领域双塔召回 + Pailitao-style ID supervision 用于同款 + TIGER/TGQ-style 抗噪训练 + channel-aware LTR 融合 + Qwen/Pailitao-style reranker 做 TopK 精排。生成式召回和 MLLM 属性 RL 放在灰度通道和数据生产链路中，待长期稳定后再扩大职责。
